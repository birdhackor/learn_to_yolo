# 從小 CNN 到 MiniYOLO：教學大綱第二版

修訂日期：2026-10-02。這是本輪教材採用的課綱；已依序撰寫小節並建立簡化模型與 CPU 實驗。正式入口見 [閱讀路線](../learning-path.md)，已驗證範圍見 [實驗狀態](../status.md)。修訂依據見 [讀者回饋與來源](./feedback.md)，前一輪官方課程研究見 [公開教材研究](./course-research.md)。

## 專案要讓讀者帶走什麼

讀者已有基本 Python／PyTorch、NN／CNN 概念；大學數學學過，但不用熟背。以中文、小模型、從零訓練為主，從 VGG 風格 CNN、ResNet，一路理解分類如何變成偵測，以及 YOLO 各分支的設計選擇。

完成後，讀者應能自己接起資料、模型、target、loss、解碼與評估；遇到漏檢、重複框、背景誤報時，有理由地選一項修正。每個版本都回答：改了什麼、原來卡在哪裡、得到什麼、付出什麼，以及在哪些條件下未必划算。

全程允許簡化模型。每個版本章首列出「歷史機制／本章簡化／本次實驗」，附原始來源；MiniYOLO 的結果只代表本章模型與資料。YOLO 的版本來自不同團隊與分支，版本號不表示單一路線，也不保證後者在所有需求下較好。

## 閱讀路線與章節節奏

- **第一階段：靜態圖片的最小閉環。** 第 0–7 章完成能從零學習的 grid detector；第 8 章能接自己的圖片與資料。第 10 章的多尺度 MiniYOLO 作為較完整的早期版本成果。
- **完整演化路線。** 第 9–16 章涵蓋 v2／v3／v4／v5／v8／v10／YOLO11／v12／YOLO26。各章有小規模機制實驗；大資料長訓練另列，讀者可以分段完成。
- **整合與應用。** 第 17 章用新資料作一次自主決策；第 18–20 章為影片、tracking 與部署選修。

版本章可包含數個短單元，但**每個實驗只改一項主要機制**。用共用基線做局部對照，再視需要組合；不把所有改動一次疊上後，將結果歸因給某一個機制。

各版本章首注明「起始分支／本次改動／實驗後是否保留」，附最短前置章節。章節順序是學習順序；例如 v12 的 attention 與 YOLO26 的推論實驗可以從各自適合的共用基線開始，無須將全部歷史改動依序累積。

每個單元固定安排：問題與失敗圖 → 直覺與事前預測 → 最小實作範圍 → 可核對的檢查點 → 對照結果與成本 → 一項自主修改。章末交出可見成果與失敗例，並說明哪些結論已有證據、哪些仍不能判斷。

數學隨問題補：符號、shape、單位、小數值例子與程式位置一起出現。必懂、稍後拆解、深入選讀有清楚標記，完整推導可跳讀。

## A. 先讓一個小 CNN 真的學得動

### 0. 超短暖身：一次學習到底發生了什麼

- tensor、forward、loss、backprop、optimizer.step、train／eval；用極小數值例子連到同一段 PyTorch 計算。
- 只補本次需要的矩陣形狀、內積、偏導與鏈式法則；BatchNorm／Dropout 使用時再說明模式差異。
- **完成條件：**指出 loss 如何連到參數，確認一次更新前後參數真的改變；知道 notebook 重建 model 後也要重建對應 optimizer。

### 1. VGG 風格小 CNN：為什麼影像適合卷積

- 從局部圖樣、位置重複與參數共享，建立 Conv–ReLU–Pooling 分類器。
- 看 channel、feature map、stride、padding、receptive field；逐 block 看 H×W×C，連到參數、計算與記憶體。
- 同時建立圖片契約：RGB、HWC／CHW、dtype、像素範圍、batch。輸入尺寸、下採樣與小型 head 一起設計。
- **完成條件：**分類推論圖板、錯誤圖片、逐層 shape；能改一次寬度或下採樣，解釋結果與成本。推論圖板從這章開始，之後沿用到畫框。

### 2. 訓練診斷：先查哪裡，才不會一直瞎調參

- 固定一套簡單 optimizer／learning rate 基線，看分項或總 loss、train／validation 曲線，必要時看 activation／gradient。
- 固定排查順序：一個 batch 的圖片與標籤 → 一次 forward／loss／backward 與參數更新 → 少量資料 overfit → held-out 評估。
- 把資料／程式問題、優化問題與泛化問題分開。遇到 GPU 錯誤時，可用 CPU 的單步檢查揭露標籤或 shape 問題。
- **完成條件：**能指出一個失敗案例的下一個檢查點。少量 overfit 是必要線索，後面仍要檢查座標、完整管線與泛化。

### 3. 小型 ResNet：先分清兩種 shortcut

- 先在相同 shape 教 `y=x+F(x)`，用 `F(x)=0` 理解 identity；再教跨 stage 的 `y=P(x)+F(x)`，畫出兩支的 shape。
- projection 是學得的轉換，不能把它解釋成逐值複製原輸入。
- 先接合法 forward，再比較 plain／residual。兩者都從零訓練，固定資料與訓練預算，記錄容量及計算差異。
- **完成條件：**能解釋 identity／projection 的用途，交出對照。小模型沒有明顯改善也可完成，重點是能說明觀察與限制。

## B. CNN 如何變成可訓練、可評估的 detector

### 4. 從分類到單物件定位：空間資訊去哪了

- 同一個 backbone，從整張圖一個類別，擴充成類別＋四個框座標；短對照 global pooling 與保留空間輸出的需求。
- bbox 的 `xyxy`／`cxcywh`、像素／正規化座標、IoU、定位 loss；分開看分類與定位 loss，避免只看相加總值。
- **完成條件：**預測／真值框疊圖，並將一張非正方形圖片的已知框經 resize／padding、還原回原圖，檢查位置。

### 5. 多物件偵測：輸出數量、背景與責任分配

- 物件數不固定、同格多物件、背景、重複預測；介紹 backbone／neck／head，短對照 sliding window、two-stage／single-stage。
- 用一張固定兩物件圖，把 annotation → 候選位置 → assignment → 正／負／ignore → target → head 各軸串起來。
- 明說哪些位置學框、哪些學類別、哪些提供背景訊號；分數定義依本章模型而定。anchor slot 與 class 維度獨立，anchor 不綁某一類。
- **完成條件：**能手填少量 target，指出哪個預測負責誰；用同格兩個同類物件展示第一版的容量限制。

### 6. 先用人工框學推論與評估

- 解碼、score filtering、NMS、框還原；用人工預測看高分錯框、重複框、漏檢和背景誤報。
- 分開三件事：訓練 assignment 決定監督誰；NMS 處理推論重複框；評估 matching 判定 TP／FP／FN。三者可以使用 IoU，但用途與規則不同。
- 手算 precision／recall、PR 曲線與簡單 AP50；再介紹多類別 mAP、COCO 的多 IoU 門檻 AP。模型輸出的 confidence 不是 precision。
- 區分顯示 score 門檻、評估的候選截斷、NMS IoU 與評估 matching IoU；版本比較固定評估協議。
- **完成條件：**能解釋為何「框看起來少了」不一定是進步，能核對一個含漏檢與重複框的計分例子。

### 7. 第一隻 grid MiniYOLO：拆成能逐段驗證的里程碑

採 YOLOv1 風格的 grid／直接回歸教學模型；head、分數、loss 與責任規則的簡化逐項標明。

1. **資料正確：**先可控幾何圖形，再小型真實資料。看原圖／輸入圖／標註疊圖；處理空圖片、變動物件數與非正方形圖片。
2. **監督正確：**沿第 5 章同一張圖生成 target；看 class id、正負與 ignore 的表示、loss mask 及各軸意義。
3. **loss 有意義：**用人工 prediction 核對框／類別／背景相關 loss；說明量綱、權重、batch reduction 與有效樣本數。
4. **真的會學：**先少量 overfit；追蹤分項 loss、正樣本數、框分布、正負位置分數。用「全部預測背景」示範檢查順序。
5. **推論接得起來：**dataset → model → decode → filtering／NMS → 原圖畫框；查看 batch=1、batch>1，以及零／一／多物件的介面。
6. **有獨立評估：**固定 held-out 小資料的 AP50／PR、成功與失敗圖板。展示成果與效果評估各自標明。

**完成條件：**從零訓練後能在未參與訓練的圖片上觀察到正確偵測，能交代漏檢／誤報；僅有隨機模型輸出框不算完成。數值門檻與資源規格待原型實測後制定。

### 8. 換成自己的圖片與資料

- 先用既有模型看自己的圖片，再分開處理「新增類別、標註後重新訓練」。
- 只提供一種簡單標註契約與固定類別對應；看漏標、錯標、空圖片與框越界。
- 固定 train／validation／test；同一影片或相近連拍按來源分組，避免相近畫面分散造成資料洩漏。
- **完成條件：**小批資料通過標註疊圖、少量 overfit 與獨立圖片推論，知道問題先落在哪個階段。

## C. 用同一個 MiniYOLO 研究演化機制

下列是選題安排。正式撰寫前，每個單元仍須逐項對照對應版本的論文／官方實作；本輪學生心得研究不等於已完成所有現代架構的原文查證。

| 章節 | 核心問題與小實驗 | 要比較的收益與代價 |
| --- | --- | --- |
| 9. YOLOv2 | 尺寸先驗怎麼幫助回歸？依序拆 anchor、target／offset、尺寸聚類；用少量候選追蹤正／負／ignore | 回歸起點與形狀覆蓋；先驗設定、assignment 複雜度、分布轉移 |
| 10. YOLOv3 | 單一尺度為何漏小物件？加入多尺度特徵與預測；同一個 pixel 框在不同 stride 下 encode／decode | 尺度覆蓋；計算、記憶體與更多候選框 |
| 11. YOLOv4／v5 | 分成四個單元：CSP、特徵融合、圖與框同步 augmentation、IoU 類 loss。逐項對照，最後才組合 | 表達能力、訓練資料多樣性與定位目標；算力、資料處理與調參成本 |
| 12. YOLOv8 相關設計 | 分成候選位置／框表示的 anchor-free、decoupled head、sample assignment、DFL 四個短單元 | 減少手工 anchor 設定、分工與定位表示；複雜度轉移到 assignment、分布式回歸及訓練 |
| 13. YOLOv10 | 先比較一對多／一對一監督，再研究 dual assignment 與 NMS-free 推論 | 減少後處理；訓練分支、配對與學習難度，不能只關掉 NMS 就視為完成 |
| 14. YOLO11 | 選一個有代表性的特徵提取／融合模組做局部替換，完整配置作導讀 | 特徵品質與效率；模組成本、參數與整體配置的混合影響 |
| 15. YOLOv12 | 用小張量追蹤 feature map → 空間 token → Q／K／V、相似度與加權 → 還原 feature map，再比較 CNN、一般 attention、Area Attention；另選簡化聚合實驗 | 互動範圍與表達；計算、記憶體、解析度與硬體實作的影響 |
| 16. YOLO26 | 推論側分 DFL-free 與推論 head；NMS-free 沿用第 13 章概念。訓練側將 Progressive Loss／STAL／MuSGD 等逐項查證、拆開，核心實驗先選一項 | 推論路徑、部署需求與訓練補強；定位表示、訓練設定、優化器與公平比較成本 |

每版沿用一張設計表：**候選位置／框表示／正樣本分配／head 與分數／推論篩選**。第 12 章直接對照早期 grid detector：兩者都沒有預設 anchor 尺寸，不表示輸出與監督設計相同。anchor-free 仍需要 assignment，也不自動意味著 NMS-free。

第 11、12、16 章的短單元分別有出口；較長的完整配置訓練為延伸實驗。版本涵蓋仍完整保留，讀者不用一次完成所有大規模實驗。

## D. 把理解變成選擇，再走向應用

### 17. 靜態偵測結業任務

給一組新資料與品質／速度需求，讀者選既有 MiniYOLO 分支，建立 baseline，檢視小物件、重疊、背景誤報等失敗，再只做一項有理由的修正。

**交付：**選擇理由、固定評估結果、成功／失敗圖、端到端時間與成本、是否保留改動。若未改善，要能指出假設、實驗能支持的範圍及下一個檢查。

### 18. 影片／攝影機串流

沿用圖片 detector，加入讀取、縮放、逐幀推論與輸出；測量前處理、模型、後處理與顯示時間，觀察解析度、frame rate 和延遲。

### 19. 簡易 tracking

從 IoU 配對與 track ID 開始，用遮擋、交叉與漏檢看 ID switch；短介紹介入運動模型或外觀特徵的理由與成本。偵測品質與追蹤品質分開評估。

### 20. ONNX／TensorRT 部署選修

先驗證 ONNX 與 PyTorch 的前處理、輸出與後處理一致，再研究動態 shape、精度選項與 TensorRT。量測同一設備的端到端延遲；batch throughput 與單張 latency 分開。TensorRT 使用的設備規格另列。

### 選修與更新入口

v6／v7／v9 可用來補重參數化、訓練輔助與梯度設計；其他分支與 YOLO26 之後的版本，依可核實原文與公開實作加入，注明查核日期及成熟度。附半頁分類／segmentation／keypoint 的 head 遷移圖即可；後續版本不只為版本號再複製整套訓練章。

## 貫穿全書的資料、檢查與實驗約定

**同一個物件一路走到底。** 原始標註 → 前處理後框 → cell／candidate／anchor → target 與 mask → head → loss → decoded boxes → score／NMS → 原圖 → 評估。每次只更新本單元改動的部分，保留欄位、單位、shape 與類別索引對照。圖片使用明確的 NCHW 契約；annotation 支援每張不同數量與零物件。

**沿用固定困難場景。** 小物件、同格多物件、極端長寬比、重疊、背景誤報、非正方形輸入與空圖片。先人工已知答案，再控制場景訓練，再真實資料評估；同一 seed、資料切分與預算作比較，小差異需要更多證據。

**實驗紀錄保持短。** 事前假設、改動、評估協議、效果、時間／記憶體／參數、是否保留及理由。候選框數、額外設定與程式複雜度也算成本；沒有改善與不能下結論的結果都保留。

**資源規格待實測。** 每單元列快速機制驗證和較完整效果比較的資料量、輸入尺寸、batch、步數／epochs、參考硬體、時間與峰值記憶體。原型量測前標「待測」，不承諾幾分鐘或某款 GPU 一定足夠。快速路徑列出通過與停止條件，達到明確檢查點即可停；完整比較另訂目的，避免無止境刷分。

**repo 維持透明。** 少量 Python 模組保存 dataset／model／targets／loss／decode／metrics／train；notebook 用於看圖與小實驗。幾何資料可控生成，小型真實資料目前以 Pascal VOC 子集為候選；資料選型與規模在最小原型時決定。
