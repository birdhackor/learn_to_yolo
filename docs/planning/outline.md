# 從小 CNN 到 MiniYOLO：課程大綱

本頁說明全書第 0–20 章、共 42 節的設計：每章要解決什麼問題、做哪些實驗，第 0–8 章讀到哪裡算完成、第 17 章結業任務要交付什麼，以及課程刻意不做的事。逐節的閱讀順序見[完整閱讀路線](../learning-path.md)，哪些結果有實測見[驗證範圍](../status.md)，設計依據見[公開課程研究](./course-research.md)與[讀者與學習心得](./feedback.md)；遇到不熟的術語，可以查[術語快速查](../glossary.md)。

## 課程要讓讀者帶走什麼

讀者只需要會基本 Python；跑過 PyTorch 範例、聽過神經網路與卷積，讀起來會比較輕鬆。數學用到高中程度的函數、對數、向量與矩陣乘法，導數與連鎖律在第 0 章從數字例子講起。課程以中文、小模型、從零訓練為主，從 VGG 風格 CNN、ResNet，一路理解分類如何變成偵測，以及 YOLO 各分支的設計選擇。

讀完後，讀者應能自己接起資料、模型、target、loss、解碼與評估；遇到漏檢、重複框、背景誤報時，能有理由地選一項修正。每個版本章都說明改了什麼、原來卡在哪裡，以及得到的收益與付出的代價。

全程使用簡化模型。版本章各節交代歷史機制與原始來源、做了哪些簡化，以及該節的實驗做什麼；MiniYOLO 的結果只代表該節的模型與資料。YOLO 的版本來自不同團隊與分支，版本號不表示單一路線，也不保證較新的版本在所有需求下都比較好。

## 閱讀路線與章節節奏

- **先取得一個成果。** 第 0–7 章完成能從零學習的 grid detector（把圖切成格子、每格各自預測框的偵測器）；第 8 章接上自己的圖片與資料。
- **完整演化。** 第 9–16 章涵蓋 v2／v3／v4／v5／v8／v10／YOLO11／v12／YOLO26 的代表機制，每節都是小規模的機制實驗。
- **整合與應用。** 第 17 章是靜態偵測的結業任務，前置只需第 6–7 章；第 18–20 章是影片、tracking 與部署，可按需求挑讀。

版本章可以分成幾個短節，但**每個實驗只改一項主要機制**：各節從一個簡化的起點做局部對照，不把幾項改動疊在一起後，再把結果歸因給其中一項。和起點還有其他差異時，該節會寫明，例如第 10 章的兩尺度模型是另外寫的小網路。

每節開頭寫明前置章節；版本節另寫明起點，也就是從哪個簡化設定出發。章節順序是學習順序，不是改動要依序累積的順序；例如 v12 的 attention 與 YOLO26 的推論實驗，各自從適合的起點開始。

每節大致照這個順序：要解決的問題 → 直覺與能手算的小例子 → 最小實作 → 可核對的輸出 → 收益與代價 → 自主練習與參考答案。每節的完整程式都用斷言（assert）核對關鍵的數字與 shape；正文也寫明實驗的範圍與簡化。

數學隨問題出現：符號、shape、單位、小數值例子與對應的程式放在一起。與原版的差異、延伸說明和較長的推導，常收在可摺疊的說明框裡；練習的參考答案也放在摺疊框中。

## A. 先讓一個小 CNN 真的學得動

### 0. 超短暖身：一次學習到底發生了什麼

- tensor、forward、loss、backward、`optimizer.step()`、train／eval；用一個參數的手算例子，連到同一段 PyTorch 計算。
- 只補這一步需要的 shape、內積、偏導與連鎖律。train／eval 只說明模式切換：Dropout、BatchNorm 這類層在兩種模式下行為不同，本課程的模型沒有用到它們。
- **完成條件：**指出 loss 如何連到參數，確認一次更新前後參數真的改變；知道在 notebook 重建 model 後，也要重建對應的 optimizer。

### 1. VGG 風格小 CNN：為什麼影像適合卷積

- 從局部圖樣、位置重複與參數共享，建立 Conv–ReLU–Pooling 分類器。
- 看 channel、feature map、stride、padding、receptive field；逐層看 shape，算出參數、乘加數與記憶體。
- 同時建立圖片契約：RGB、HWC／CHW、dtype、像素範圍、batch。
- **完成條件：**分類推論圖板、錯誤圖片、逐層 shape；能把寬度加倍，手算參數與計算量怎麼變。推論圖板從這章開始，之後的章節沿用到畫框。

### 2. 訓練診斷：先查哪裡，才不會一直瞎調參

- 固定一套簡單的 optimizer 與 learning rate，看分項或總 loss、train／validation loss，必要時看梯度。
- 固定排查順序：一個 batch 的資料與標籤 → 一次 forward／loss／backward 與參數更新 → 少量資料 overfit → held-out 評估。
- 把資料／程式問題、最佳化問題與泛化問題分開。遇到 GPU 錯誤時，可用 CPU 的單步檢查揭露標籤或 shape 問題。
- **完成條件：**能指出一個失敗案例的下一個檢查點。少量資料 overfit 成功，只說明管線與容量大致沒問題；後面仍要檢查座標、完整管線與泛化。

### 3. 小型 ResNet：先分清兩種 shortcut

- 3.1 在相同 shape 下教 `y=x+F(x)`，用 `F(x)=0` 理解 identity；3.2 再教跨 stage 的 `y=P(x)+F(x)`，畫出兩支的 shape。
- projection 是學得的轉換，不能解釋成逐值複製原輸入。
- 3.3 比較 plain 與 residual：兩者從同一份初始權重開始，固定資料與訓練預算，並記錄參數與計算成本。
- **完成條件：**能解釋 identity 與 projection 各自的用途，交出對照。小模型沒有明顯改善也可以完成，重點是能說明觀察與限制。

## B. CNN 如何變成可訓練、可評估的 detector

### 4. 從分類到單物件定位：空間資訊去哪了

- 4.1 用同一個 backbone，從整張圖一個類別擴充成類別＋四個框座標；對照 global average pooling 與保留空間排列的框 head。
- bbox 的 `xyxy`／`cxcywh`、像素與正規化座標、IoU、定位 loss；分類與定位 loss 分開看，不只看相加後的總值。
- **完成條件：**畫出預測框與真值框的疊圖；4.2 把一張非正方形圖片的已知框經 resize／padding 轉到輸入畫布，再還原回原圖，檢查位置。

### 5. 多物件偵測：輸出數量、背景與責任分配

- 物件數不固定、同格多物件、背景、重複預測；介紹 backbone／neck／head，並簡短對照 sliding window、two-stage 與 single-stage。
- 用一張固定的兩物件圖，把標註 → 候選位置 → assignment（責任分配） → 正／負樣本 → target → head 各軸串起來；ignore（某項 loss 完全不算的候選）到第 9 章才用到。
- 明說哪些位置學框、哪些學類別、哪些提供背景訊號；分數的定義依本章模型而定。slot（一個能輸出一組框與分數的位置）與類別是獨立的軸：每個 slot 都輸出全部類別的分數。
- **完成條件：**能手填少量 target，指出哪個預測負責哪個物件；用同格兩個同類物件，展示每格只有一個 slot 的容量限制。

### 6. 先用人工框學推論與評估

- 6.1 解碼、score 篩選、NMS 與框還原；本章用人工預測看高分錯框、重複框、漏檢與背景誤報。
- 分開三件事：訓練時的 assignment 決定監督誰；推論時的 NMS 處理重複框；評估時的 matching 判定 TP／FP／FN。三者都可能用到 IoU，但用途與規則不同。
- 6.2 手算 precision／recall、PR 曲線與 AP50，再介紹多類別 mAP 與 COCO 的多 IoU 門檻 AP。score 不是 precision。
- 區分顯示門檻、評估候選截斷門檻、NMS 的 IoU 門檻與配對 IoU 門檻；評估規則不同時，算出的 AP 不能直接比較。
- **完成條件：**能解釋為何「框看起來變少了」不一定是進步，能核對一個含漏檢與重複框的計分例子。

### 7. 第一個 grid MiniYOLO：拆成能逐段驗證的里程碑

採 YOLOv1 風格的格子與直接回歸教學模型；head、分數、loss 與責任規則的簡化逐項標明。六個里程碑依序對應 7.1–7.6 節：

1. **資料正確（7.1）：**用可控的幾何圖形，依標註重畫畫素再逐值比對；保留空圖片，每張圖的物件數可以不同。
2. **監督正確（7.2）：**沿用 7.1 的固定場景生成 target；看 class id、正格與負格（這個版本沒有 ignore）、loss mask 及各軸意義。
3. **loss 有意義（7.3）：**用人工 prediction 手算框、objectness（物件分數）與類別三項 loss；說明單位、權重、取平均的分母，以及整批都沒有正格時的處理。
4. **參數真的會更新（7.4）：**3 步更新確認 forward、backward、`optimizer.step()` 都真的執行；追蹤分項 loss 與正、負格的 objectness 平均，並用「全部預測背景」示範檢查順序。
5. **推論接得起來（7.5）：**模型 → 解碼 → 分數篩選 → 各類 NMS；用答案已知的人工 logits 核對框與分數，涵蓋 batch=1、batch>1，以及零、一、多個物件。
6. **有獨立評估（7.6）：**先用答案已知的人工例子核對評估器，再接上模型，在沒參與訓練的 held-out 圖片上評估。

**完成條件：**從零訓練後，能在未參與訓練的圖片上看到正確偵測，並交代漏檢與誤報；只有隨機模型輸出的框不算完成。[7.4 節](../lessons/07-training.md)的 160 步合成資料訓練提供這項證據：設定、訓練時間、獨立 validation／test 結果與失敗圖都在該節；這些結果不外推成真實照片或原版 YOLO 的成績。

### 8. 換成自己的圖片與資料

- 8.1 先把自己的非正方形圖片送進同架構的模型：讀圖、轉成 RGB 與 CHW、letterbox、推論，再把框還原回原圖。8.2 才處理「新增類別、標註後重新訓練」。
- 只提供一種簡單的 JSON 標註格式與固定的類別順序；框越界、類別編號不合法這類結構錯誤由程式擋下，漏標與框錯位則要畫標註疊圖用眼睛查。
- 固定 train／validation／test，並按來源切分：同一段影片或相近連拍的圖要整組放在同一邊，避免相近畫面造成資料洩漏。
- **完成條件：**一小批資料通過標註疊圖、少量 overfit 與獨立圖片推論，並知道問題先落在哪個階段。

## C. 用小實驗研究 YOLO 的演化機制

第 9–16 章各節的機制都對照原論文或固定版本的官方程式，並說明本節的簡化和原版差在哪裡；審查方式與紀錄見[全套實驗與審查](../validation/curriculum.md)。公開學習者的心得只用來安排教學，不替代技術查證。

| 章節 | 核心問題與小實驗 | 要比較的收益與代價 |
| --- | --- | --- |
| 9. YOLOv2 | 尺寸先驗怎麼幫助回歸？9.1 把寬高改成相對 anchor 的修正量，每格兩個 slot，追蹤正樣本、ignore 與負樣本；9.2 用 1−IoU 當距離做尺寸聚類 | 回歸起點與形狀覆蓋；先驗設定、assignment 複雜度，資料分布改變時先驗也未必合適 |
| 10. YOLOv3 | 單一尺度為何漏小物件？加一個 8×8 的細尺度 head，同一個 pixel 框在 stride 8 與 16 下 encode／decode；推論時合併兩個 head 的框再做 NMS | 尺度覆蓋；計算、記憶體與更多候選框 |
| 11. YOLOv4／v5 | 分成四個獨立單元：CSP（只讓一部分 channel 經過整串卷積）、特徵融合、圖與框同步增強、IoU 類 loss；每單元只改一項，不組合成一個模型 | 表達能力、訓練資料多樣性與定位目標；算力、資料處理與調參成本 |
| 12. YOLOv8 相關設計 | 分成 anchor-free（候選點到框四邊的距離）、decoupled head（框與類別分成兩條分支）、sample assignment、DFL（把一條邊的距離學成一組機率）四個短單元 | 減少手工 anchor 設定、分工與定位表示；複雜度轉移到 assignment、分布式回歸與訓練 |
| 13. YOLOv10 | 13.1 比較一對多與一對一監督，研究 dual assignment；13.2 看拿掉 NMS 之前，重複候選的分數怎麼被壓低 | 減少後處理；訓練分支、配對與學習難度，不能只關掉 NMS 就視為完成 |
| 14. YOLO11 | 拆開 C3k2 模組的「切分→轉換→串接」，單獨測這個模組，並和兩層普通 3×3 卷積比較參數與計算量 | 保留轉換程度不同的特徵；參數、計算量與中間特徵的記憶體，整版的收益也不能只歸給這個模組 |
| 15. YOLOv12 | 用小張量追蹤 feature map → token → Q／K／V、相似度與加權 → 還原 feature map；再比較 full attention、Area Attention 與 3×3 卷積每層讀得到哪些位置 | 互動範圍與表達；計算、記憶體、解析度與硬體實作的影響 |
| 16. YOLO26 | 推論側分 DFL-free 與推論 head，NMS-free 沿用第 13 章；訓練側說明 Progressive Loss（把 loss 權重從一對多分支逐步移向一對一分支）、STAL（照顧小物件的候選分配）與 MuSGD（Muon 與 SGD 混合的優化器），只對 Progressive Loss 做實驗 | 推論路徑、部署需求與訓練補強；定位表示、訓練設定、優化器與公平比較的成本 |

讀版本章時，可以沿五個設計軸對照：**候選位置、框表示、正樣本分配、head 與分數、推論篩選**。第 12 章直接對照第 7 章的 grid detector：兩者都沒有預設的 anchor 尺寸，但輸出與監督設計並不相同。anchor-free 仍需要 assignment，也不自動代表 NMS-free。

第 11、12、16 章拆成幾個短節，每節各做一個小實驗；課程不訓練各版本的完整配置。第 9–16 章都屬於完整演化路線，可以一節一節讀。

## D. 把理解變成選擇，再走向應用

### 17. 靜態偵測結業任務

給定一組合成資料（train／validation／test 各用不同的 seed 產生）與需求（偵測紅、藍矩形，並量出單張圖從輸入到畫好框的時間）：先說明為什麼選第 7 章的 GridDetector 當 baseline，再檢視它的漏檢、定位不準與背景誤報，提出假設、事先寫好保留規則，只改一項重新訓練，用 validation 決定保不保留，最後只對選定的模型評一次 test。

**交付：**選擇理由、固定評估協議下的結果、成功與失敗圖、端到端時間與成本、是否保留改動。若沒有改善，要能指出假設、實驗能支持的範圍與下一個檢查。

### 18. 影片串流

沿用圖片 detector，加入逐幀讀取、縮放、推論與畫框；分段量測前處理、模型、後處理與畫框的時間，分清處理速率與延遲，並看處理比來源慢時，排隊怎麼讓延遲越來越大。主例用程式畫的影片，另有一次把畫面寫成真的影片檔再讀回的檢查；相機 adapter 有提供，但沒有接實體攝影機測試。

### 19. 簡易 tracking

從 IoU 配對與 track ID 開始，用兩個同類物件交叉與一次漏檢看 ID switch；再比較只看上一幀的框與先用速度預測位置兩種配對。外觀特徵與 Kalman filter 只簡短說明理由與成本。偵測品質與追蹤品質分開評估；最後把第 18 章模型的真實逐幀預測接上 tracker。

### 20. ONNX／TensorRT 部署選修

先在 CPU 上驗證 ONNX Runtime 與 PyTorch 的 raw 輸出、解碼後的框，以及還原到原圖的框都一致，再看動態 batch 與固定空間尺寸、精度選項與 TensorRT。量測時分清模型本身與整條流程，batch 的吞吐量與單張的延遲也分開。TensorRT 另外在一張雲端 NVIDIA L4 上實測，使用的 GPU、版本與比對結果列在該節。

## 貫穿全書的資料、檢查與實驗約定

**同一個物件一路走到底。** 首頁示意圖的紅框 `[8,12,24,28]` 從 7.1 的標註出發，依序變成 7.2 的 target 與 mask、7.3 的 loss、7.5 的解碼結果與 7.6 的評估例子；9.1、11.3、11.4 節也沿用它。每一站都寫明欄位、單位、shape 與類別索引。送進模型的圖片一律是 NCHW；標註允許每張圖的物件數不同，也允許零個物件。

**困難情境先用已知答案。** 空圖、同格兩個物件、非正方形輸入、小物件、重複框與背景誤報，多半先用答案已知的人工小例子呈現，再到程式生成的受控資料上短訓練。比較時固定 seed、資料切分與訓練預算；小差異需要更多證據。

**需要做決定的實驗，先寫協議。** 例如第 17 章先寫下假設、唯一的改動、評估協議與保留規則，再看結果；時間、參數與候選數也算成本。沒有改善或不能下結論的結果照樣保留，例如 8.2 節只訓練 160 步、沒學好的那次結果。

**資源規格以實測為準。** 各節的完整程式都只用 CPU 執行，資料量與訓練步數都很小；用到 GPU 的只有另外在雲端 NVIDIA L4 上做的兩項檢查：GPU／checkpoint 實測，以及第 20 章的 TensorRT 一致性（見下方〈課程刻意不做的事〉）。部分節附上實際量到的時間，那只代表紀錄裡的那台電腦；課程不承諾幾分鐘內跑完，也不承諾某款 GPU 一定足夠。第 2 章與第 17 章寫明做到哪裡就可以停，避免無止境刷分。

**程式結構公開可查。** 共用的資料、模型、target、loss、解碼、評估與訓練程式放在 `miniyolo/` 套件；每節的完整實驗是 `lesson_cases/` 裡的一支程式，Colab notebook 的最後一格就是同一份程式，並存著執行紀錄的輸出。幾何資料由程式依固定 seed 生成。

## 課程刻意不做的事

- **不在真實照片的偵測資料集上訓練。** 偵測實驗都用程式生成的合成圖或小型自製資料。Penn-Fudan、Pascal VOC、COCO 這類資料集的來源、授權與切分規則記在[資料規劃](../preparation/data.md)，課程沒有用它們訓練或評估。
- **不重現完整版本。** 版本章只拆出單一機制做小實驗，不訓練各版本的完整配置，所以不報告版本之間的 AP 或速度排名，也不為了版本號重做整套訓練章。
- **只涵蓋列出的版本與任務。** YOLOv6、v7、v9 的重參數化、訓練輔助與梯度設計不在範圍內；segmentation（分割）、keypoint 姿態估計與半監督學習也不在範圍內。第 12–16 章對照的官方程式固定版本，見[版本來源查證](../research/version-sources.md)。
- **部署與影片只做到小規模檢查。** INT8 只說明、沒有實測；相機只提供 adapter，沒有接實體攝影機。GPU 上只在雲端 NVIDIA L4 做過兩項小規模檢查：第 20 章的 TensorRT 一致性，以及 [GPU／checkpoint 實測](../validation/gpu-smoke.md)的短訓練與存檔續訓。
- **沒有真人學生的學習成效研究。** 教材的審查者都是 AI。
