# 15.1 Feature map 到 attention：四個位置怎麼互相讀取

[在 Colab 執行本節](https://colab.research.google.com/github/birdhackor/learn_to_yolo/blob/lessons-v0.6.0/notebooks/15-attention-bridge.ipynb){ .md-button }

3×3 卷積在每個位置都用同一組濾鏡，一層只讀以自己為中心的 3×3 格。這組權重訓練完就固定，不管輸入哪張圖都一樣。特徵圖很大時，要讓左上角知道右下角的資訊，得疊很多層卷積。attention（注意力）換一種讀法：每個位置一層就能讀所有位置，而且「讀誰多一點」是用當下的特徵算出來的，換一張圖就不同。

本節用一張 2×2 的小特徵圖，把 attention 完整算一次：先把四個位置排成四列，算出第一個位置從四個位置各讀多少、讀到什麼，再還原成圖，並確認梯度傳得回去。讀完你能手算一列 attention 權重和輸出，也能說明它的成本為什麼隨位置數的平方成長。

前置：知道 feature map 的 `[B,C,H,W]` 四個軸、會算矩陣乘法、知道 softmax 怎麼把一組分數變成加總為 1 的比例（[DFL 那一節](12-dfl.md)用過），也知道 backward 會算出梯度（[暖身那一節](00-warmup.md)）。

本節用最簡單的版本：只有 2 個 channel 和一套 Q、K、V（下面說明），每個位置都讀全部位置（full attention）。先把計算弄懂；只讓同一區域內互相讀取的做法，留到下一節。

??? note "本節簡化了什麼"

    本節對照的原版是 YOLOv12 的 attention 設計，起點是 CNN 輸出的 feature map。和原版相比，本節做了這些簡化：

    - **單 head**：這裡的 head 是 attention head（注意力頭），和前面章節的偵測 head 無關。一個 attention head 是一套 Q、K、V，加上它算出的一張 N×N 權重表（N 是位置數；Q、K、V 和這張表，下面都會實際算出來）。多 head 是把 channel 分成幾組，各算各的權重表，再把結果接起來，細節見[下一節](15-area-attention.md)的多 head 延伸說明。本節只有一個 head。
    - **只有 2 個 channel**：方便手算。
    - **投影的初值是單位矩陣**：Q、K、V 各由一份可學的投影矩陣產生。本節把三份投影的初值都設成 2×2 單位矩陣（identity：乘上去，輸出等於輸入），所以一開始 Q、K、V 都等於輸入。
    - **普通的 full attention**：每個位置都和全部位置（含自己）算權重。
    - **沒有多 head，也沒有位置卷積**：位置卷積是 YOLOv12 用來補位置資訊的卷積，在〈互動更遠，成本也更快成長〉那段說明。
    - **不是完整的 YOLOv12**：實驗只驗證兩件事，一是輸出確實是各位置內容的加權和，二是梯度確實傳得回投影參數，而且 Q、K、V 三塊投影收到的梯度各不相同。限制每個位置能讀的範圍，是下一節的事。

![從空間特徵到加權輸出的 shape 路徑，以及左上從四個位置各讀多少](../assets/diagrams/15-attention-bridge.svg)

看圖時注意兩點：V 不經過 softmax，是直接拿到最後的 weights @ V 使用；這裡的 @ 是矩陣乘法，不是逐元素相乘。下方小圖是權重表的第 1 列，也就是左上從四個位置各讀多少；這四個數會在下面〈真正算第一個位置的權重〉手算出來。

## 空間位置變成列，channel 變成特徵

輸入 `[B,C,H,W]=[1,2,2,2]`：1 張圖、2 個 channel、高和寬各 2。channel0 為 `[[1,0],[1,0]]`，channel1 為 `[[0,1],[1,0]]`。attention 要在位置之間讀取，所以先把每個位置的 channel 值排成一列：把 H、W 攤平成 N=4 個位置，再交換 C 和 N，得到 tokens `[1,4,2]`。一個 token 就是一個位置上各 channel 的值排成的向量，本例每個 token 有 2 個數。四個 token 依序是左上 `[1,0]`、右上 `[0,1]`、左下 `[1,1]`、右下 `[0,0]`。

``` { .python data-excerpt="lesson_cases/15-attention-bridge.py" }
tokens = feature.flatten(2).transpose(1, 2)  # [1,2,2,2] → [1,2,4] → [1,4,2]
```

軸從 0 數起：0 是 B、1 是 C、2 是 H、3 是 W。`flatten(2)` 把第 2 軸（H）以後的軸併成一軸：`[1,2,2,2]`→`[1,2,4]`。併的順序是 row-major：由上而下逐列、每列由左到右，也就是左上→右上→左下→右下。`.transpose(1, 2)` 交換第 1 軸和第 2 軸（C 和 N），得到 `[1,4,2]`。

這一步沒有學到新特徵，只是重新排列；之後還原成圖時，也要照同樣的順序。`transpose` 只交換兩個軸，是 `permute`（重排所有軸的順序）的特例。`reshape` 則只把數值照原本的排列順序重新切段，不會對調軸，不能拿來代替 `transpose`。如果直接寫 `feature.reshape(1,4,2)`，shape 一樣是 `[1,4,2]`，內容卻是 `[[1,0],[1,0],[0,1],[1,0]]`。每個「token」其實是某一個 channel 裡同一列的兩個值（例如第一個是 channel0 上面那一列），不是同一個位置的兩個 channel；和正確的 tokens 相比，只有第一個碰巧相同。shape 合法，位置卻全部錯置。

接著每個 token 要變出三份向量：Q＝query（查詢：這個位置想找什麼）、K＝key（鍵：每個位置拿來被比對的標籤）、V＝value（值：真正被讀走的內容）。Q、K 決定讀取比例，V 供應實際讀到的內容。可以想成查資料：拿自己的 query 去和每個位置的 key 比對、打分數，分數決定從那個位置讀多少，讀到的是那個位置的 value。

這三份向量由 QKV 線性投影算出。程式用 `qkv = nn.Linear(2, 6, bias=False)` 把每個 2 維 token 轉成 6 維，再切成 Q、K、V 各 2 維，shape 都是 `[1,4,2]`。這等於把三個 2→2 的線性層合成一次算：權重是 6×2 矩陣，由三個 2×2 單位矩陣 `[[1,0],[0,1]]` 上下疊成（完整程式寫 `torch.eye(2).repeat(3, 1)`）。所以每個 token x 會變成「x 重複三次」的 6 維向量，切成三份後 Q=K=V=x，也就是 Q、K、V 恰好等於 tokens。這裡的「投影」只是乘一個可學的矩陣，不是數學課裡把向量投到某個方向的正射影。

這三塊投影權重都是可學參數，一般訓練時會各自改變，Q、K、V 就不再相等。三份分開學，「要找什麼」「怎麼被找到」「提供什麼內容」才能各不相同；本例設成單位矩陣，只是為了方便手算。

## 真正算第一個位置的權重

先手算第一個位置（左上）要從四個位置各讀多少。它的 query 是 `[1,0]`。

1. 四個 key 就是四個 token：[1,0]、[0,1]、[1,1]、[0,0]。
2. query 和每個 key 做內積（對應元素相乘再相加），例如 [1,0]·[1,1]=1×1+0×1=1。四個內積是 [1,0,1,0]。
3. d 是每個 query／key 向量的元素個數（特徵數），本例 d=2。四個內積都除以 √d=√2，得到 [0.7071,0,0.7071,0]。
4. softmax 先對每個分數取 exp（exp(x) 就是 eˣ）：exp(0.7071)≈2.0281，exp(0)=1，得到 [2.0281,1,2.0281,1]。
5. 四項加總，得到這一列共同的分母：2×2.0281+2×1≈6.0562。
6. 每項除以分母：2.0281/6.0562≈0.3349，1/6.0562≈0.1651，得到 [0.3349,0.1651,0.3349,0.1651]，四個加起來是 1。

這四個數是左上的 attention 權重，也就是讀取比例：左上從四個位置各讀多少。它不是模型參數，每次輸入都重新算；會被訓練的是產生 Q、K、V 的投影參數 `qkv.weight`。

下面的程式片段把除以 √d 後的分數存在變數 `similarity`（相似度）。變數名字叫相似度，本質卻是內積：a·b＝|a||b|cosθ，同時受方向和長度影響；它不是只看方向的 cosθ（[decoupled head 那一節](12-decoupled-head.md)比較梯度方向時用的 cosine 就是這個）。所以 [1,1] 雖然和 [1,0] 差了 45°，長度卻是 √2 倍，內積 1×√2×cos45°=1，和 [1,0] 跟自己的內積一樣。後面練習 1 裡的 [2,0] 和 [1,0] 方向相同、長度兩倍，內積是 2，比 [1,0] 跟自己的內積還高。可學的 Q、K 投影，就是用來調整誰和誰的分數高。

```python
q, k, v = qkv(tokens).chunk(3, dim=-1)               # 切成 Q、K、V，各 [1,4,2]
similarity = q @ k.transpose(-2, -1) / math.sqrt(2)  # [1,4,4]
attention = similarity.softmax(-1)                   # 沿最後一軸（來源／key 軸）做 softmax
output_tokens = attention @ v                        # [1,4,2]
```

完整程式沒有 `similarity` 這個變數，而是把算 `similarity` 和 `attention` 的兩行併成一行：`attention = (q @ k.transpose(-2, -1) / math.sqrt(2)).softmax(-1)`。

`@` 是矩陣乘法。`k.transpose(-2, -1)` 交換最後兩軸（-1 是最後一軸，-2 是倒數第二軸），把 K 從 `[1,4,2]` 變成 `[1,2,4]`，這就是 Kᵀ（K 的轉置）。三維的 tensor 相乘時，最前面的 batch 軸各自配對（第 0 張圖配第 0 張圖），只有最後兩軸做矩陣乘法：[4,2]@[2,4]=[4,4]，所以結果是 `[1,4,4]`。

所以 `q @ k.transpose(-2, -1)` 算的是 Q 與 Kᵀ 的乘積 QKᵀ，除以 √2 後就是圖中 softmax(QKᵀ/√2) 括號裡的部分。QKᵀ 的第 i 列第 j 欄＝第 i 個 query 與第 j 個 key 的內積，所以 `similarity` 的第一列就是上面手算的 [1,0,1,0]/√2。第 i 列代表接收位置 i，第 j 欄代表來源位置 j。softmax 之後，這張 `[1,4,4]` 表記錄每一對位置之間的讀取比例；程式輸出和後面的成本段把它叫 affinity。

softmax 沿最後一軸，也就是 key（來源）軸做，所以每一列加起來是 1：每個接收者自己分配一份讀取比例。若沿 query 軸做，變成每一欄加起來是 1，就不再是「每個接收者自己選一份來源分佈」。

??? note "完整的 4×4 權重表"

    程式只印出第一列；其他三列可以照上面的步驟手算。列是接收位置、欄是來源位置，順序都是左上、右上、左下、右下：

    | 接收＼來源 | 左上 | 右上 | 左下 | 右下 |
    | --- | --- | --- | --- | --- |
    | 左上 | 0.3349 | 0.1651 | 0.3349 | 0.1651 |
    | 右上 | 0.1651 | 0.3349 | 0.3349 | 0.1651 |
    | 左下 | 0.2212 | 0.2212 | 0.4486 | 0.1091 |
    | 右下 | 0.25 | 0.25 | 0.25 | 0.25 |

    每一列加起來是 1，這就是「沿 key 軸做 softmax」。每一欄加起來不必是 1：四欄依序是 0.9712、0.9712、1.3683、0.6893。表中數字四捨五入到小數第四位，直接相加可能差 0.0001（例如第三列得 1.0001、第三欄得 1.3684）。

    右下的 query 是 [0,0]，和每個 key 的內積都是 0，所以四個位置平均讀取，各 0.25。

除以 √d，是為了在 d 變大時，分數不會大到把 softmax 推向極端（幾乎只讀一個位置）。原因見下面的摺疊區塊。

??? note "為什麼除以 √d"

    假設 q、k 的每個元素互相獨立、平均 0、變異數 1。內積 q·k 是 d 項相加，第 i 項是對應元素的乘積 qᵢkᵢ。每一項的平均是 0、變異數是 1，理由如下（E[·] 表示平均，也就是高中機率的期望值）：

    - 變異數＝平方的平均－平均的平方。平均是 0 時，變異數就等於平方的平均，所以 E[qᵢ²]=E[kᵢ²]=1。
    - 兩個互相獨立的量，乘積的平均等於平均的乘積：E[qᵢkᵢ]=E[qᵢ]E[kᵢ]=0×0=0。
    - qᵢ²、kᵢ² 也互相獨立，同樣可以拆開：E[(qᵢkᵢ)²]=E[qᵢ²]E[kᵢ²]=1×1=1。qᵢkᵢ 的平均是 0，所以這個平方的平均就是它的變異數。

    互相獨立的量相加時，變異數也直接相加，所以內積的變異數是 d，標準差是 √d。除以 √d 之後，不管 d 是多少，分數的標準差都回到約 1。

    不除會怎樣？若 d=64，分數的標準差約 8。兩個位置的分數差 8 時，softmax([8,0])≈[0.9997,0.0003]，幾乎只讀一個位置。這時 softmax 已經飽和：分數小幅變動，比例幾乎不變，梯度也接近 0，Q、K 很難學。同樣兩個分數除以 √64=8 後是 [1,0]，softmax([1,0])≈[0.73,0.27]，仍會混合讀取。

    為什麼不除以 d？那樣分數的標準差變成 √d/d=1/√d，d 越大越縮向 0，權重就趨近平均，每個位置都讀得差不多。

    本例 d=2，看不出縮放的必要；它是為了 d 很大的時候。出處：[Attention Is All You Need](https://arxiv.org/abs/1706.03762) 3.2.1 節（Scaled Dot-Product Attention）。正文說，作者推測（原文 We suspect）d 很大時內積會變大，把 softmax 推到梯度極小的區域，所以把內積乘上 1/√d；上面的變異數推導出自該節的腳註。d=64 的數值例與「為什麼不除以 d」是本頁的補充。

第一個位置的輸出是四份 V 的加權和，權重就是剛才那一列。本例 V 就是 tokens，所以：

- 第一 channel：0.3349×1+0.1651×0+0.3349×1+0.1651×0=0.6698
- 第二 channel：0.3349×0+0.1651×1+0.3349×1+0.1651×0=0.5

程式裡 `attention @ v` 的第一列就是這個加權和。左上從第三個 token（左下）讀到的比例和讀自己一樣多（都是 0.3349），所以輸出不只是自己的複製。不過 2×2 的圖太小，3×3 卷積在左上也看得到全部四格；本例要看的是「讀多少由內容決定」。距離的差別在大圖上才明顯：16×16 的圖上，3×3 卷積一層只讀自己和周圍 8 格，attention 一層就能讀自己以外的其餘 255 格。

## 還原圖片佈局，並讓投影學一次

輸出 tokens 仍是 `[1,4,2]`。先轉回 `[1,2,4]`，再 reshape 成 `[1,2,2,2]`，就回到圖片的排法，用的也是同樣的 row-major 順序。完整程式寫成 `output = output_tokens.transpose(1, 2).reshape_as(feature)`（`reshape_as(feature)` 表示 reshape 成和 `feature` 相同的 shape），下面的 `output` 就是它。還原後和輸入的 shape 相同，所以能接回卷積網路繼續用。YOLOv12 作者程式裡包住 attention 的區塊（`ABlock`），還會把 attention 的輸出加回原特徵（`x = x + self.attn(x)`），類似[第 3 章](03-identity.md)的 residual。

為了有 loss 可以反傳，完整程式最後一段先定一個目標，算 loss、backward，再用 SGD（w←w−lr×梯度，這裡 lr=0.1）更新一次，並用斷言（assert）核對梯度與更新結果。下面是這一段，中文註解是另外加的：

``` { .python data-excerpt="lesson_cases/15-attention-bridge.py" }
optimizer = torch.optim.SGD(qkv.parameters(), lr=.1)
optimizer.zero_grad()
# 目標：feature 的 channel0 乘 1、channel1 乘 0.5
target = feature * torch.tensor([1., .5]).view(1, 2, 1, 1)
loss = F.mse_loss(output, target)
loss.backward()
# 梯度和 qkv.weight 一樣是 6×2，沿第 0 軸切成三塊 2×2：Q、K、V 各一塊
grad_q, grad_k, grad_v = qkv.weight.grad.chunk(3, dim=0)
assert all(part.abs().sum() > 0 for part in (grad_q, grad_k, grad_v))  # 每塊都不全為 0
assert not torch.allclose(grad_q, grad_k)  # 三塊兩兩不同
assert not torch.allclose(grad_q, grad_v)
assert not torch.allclose(grad_k, grad_v)
old = qkv.weight.detach().clone()  # 更新前的副本
optimizer.step()
assert not torch.equal(old, qkv.weight)  # 更新一步後，權重確實改變
```

`target` 是把 feature 的 channel1 乘 0.5。`torch.tensor([1., .5]).view(1, 2, 1, 1)` 把兩個倍數排成 shape `[1,2,1,1]`；和 `[1,2,2,2]` 的 feature 相乘時，長度 1 的 H、W 兩軸會 broadcast（廣播：自動延伸成另一邊的長度，見[第 3 章](03-identity.md)），所以每個位置都是 channel0 乘 1、channel1 乘 0.5。四個目標 token 依序（左上、右上、左下、右下）是 [1,0]、[0,0.5]、[1,0.5]、[0,0]。若漏寫 `.view(1, 2, 1, 1)`，shape `[2]` 的倍數會對齊 feature 的最後一軸，也就是寬，變成兩個 channel 右邊那一欄都乘 0.5，而不是 channel1 乘 0.5。

這個目標要求輸出還原成這張縮放過的輸入，所以叫 reconstruction target（重建目標），印出的 loss 也叫 reconstruction loss。`F.mse_loss` 算的是 MSE（mean squared error，均方誤差）：輸出與目標的 8 個值逐一相減、平方，再取平均；`F` 是完整程式開頭匯入的 `torch.nn.functional`。這個目標本身沒有偵測意義，只是用來確認梯度流得到 Q、K、V 的投影參數。

`chunk(3, dim=0)` 沿第 0 軸把梯度的 6 列切成上、中、下三塊，順序和前面把 6 維輸出切成 Q、K、V 時相同，所以依序是 Q、K、V 的投影收到的梯度 `grad_q`、`grad_k`、`grad_v`。斷言檢查三件事：每塊梯度都不全為 0；三塊兩兩不同；更新一步後 `qkv.weight` 確實改變。「不全為 0」和「比較更新前後的副本」這兩種寫法，[第 2 章](02-diagnostics.md)確認 body 有在學時也用過。這些斷言不表示 attention 學到了對偵測有用的東西，只證明加權讀取、還原和 loss 都在同一張計算圖上，而且 Q、K、V 三塊投影收到的梯度各不相同。

channel1 乘 0.5，是為了讓 Q、K 兩塊的梯度分開。本例的輸入有一種對稱：把每個 token 的兩個 channel 對調，[1,0]、[0,1]、[1,1]、[0,0] 變成 [0,1]、[1,0]、[1,1]、[0,0]，還是同樣四個 token，只是左上、右上互換位置。目標若直接用原 feature，也有同樣的對稱；三塊投影又都從單位矩陣出發，這時 Q、K 兩塊收到的梯度數學上完全相同，更新一步後 Q、K 的投影也仍然相同（float32 計算時只差捨入誤差，見下一段）。程式用的目標（channel1 乘 0.5）沒有這個對稱，算出來三塊梯度兩兩不同；三塊投影都從同一個單位矩陣出發，各自減去 0.1 倍自己的梯度，所以更新一步後 Q、K、V 的投影就各不相同，也就是前面說的「三份分開學」。不過，不是任何打破對稱的目標都行：漏寫 `.view` 時的目標 [1,0]、[0,0.5]、[1,1]、[0,0] 同樣不對稱，算出來 Q、K 的梯度卻仍然相同。所以程式不靠推理，直接用斷言核對三塊梯度兩兩不同。

比較梯度用 `torch.allclose`（逐項比較，每一項的差距都在容許誤差內就算相等，[4.2 節](04-coordinates.md)用過），不用 `torch.equal`（兩邊每個值都完全相同才算相等）。數學上相同的兩塊梯度，用 float32（PyTorch 預設的浮點數格式，約 7 位有效數字）計算時，可能因為捨入誤差而在最後幾位不同；改用 `torch.equal` 的話，`assert not torch.equal(...)` 可能照樣通過，放過 Q、K 梯度其實相同的情況。最後一條斷言比的是更新前後的權重：沒有更新時，權重的每個值都原封不動，所以用 `torch.equal` 就夠了。

執行 `PYTHONPATH=. python lesson_cases/15-attention-bridge.py`，對照印出的這幾行：

- `tokens`：順序是左上、右上、左下、右下。
- `first attention row`：[0.3349,0.1651,0.3349,0.1651]，就是上面手算的那一列（印到小數第四位）。
- `first weighted value`：[0.6698,0.5]，也就是第一個位置的輸出。
- `shape feature -> tokens -> affinity -> feature`：第三個 shape 是 affinity，`(1, 4, 4)`。
- 最後一行 `backward/step through Q,K,V verified`：程式裡的斷言全部通過，才會印出這一行，表示反傳和一次更新都成功；後面的 `reconstruction loss` 是更新前算出的 MSE。

以 `exercise` 開頭的兩行是練習 1 的答案，做練習前先別看。程式在 CPU 上就能跑，不需要 FlashAttention。FlashAttention 是在 GPU 上算 attention 的一種做法：把計算切成小塊，邊算邊做 softmax 與加權，不把整張 N×N 權重表存進記憶體。算出的結果和普通算法相同，但省記憶體，通常也比較快。

## 互動更遠，成本也更快成長

full attention 讓每個位置都和全部 N 個位置配對，所以 affinity 每張圖、每個 attention head 有 N² 個數。8×8 特徵圖 N=64，權重表有 4,096 個數；16×16 特徵圖 N=256，有 65,536 個數。空間邊長變兩倍，affinity 變 16 倍。對照 3×3 卷積：每個位置固定讀 9 格，計算量和 N 成正比，邊長變兩倍 → N 變 4 倍 → 計算約 4 倍；full attention 的配對數 N² 卻變 16 倍。

N² 是把整張權重表實際存下來時的大小。上面提到的 FlashAttention 雖然不存整張表，仍算了全部 N² 對分數；它省的是記憶體和搬資料的時間，不是位置配對數。

收益：每個位置一層就能讀任何位置，讀多少由內容決定。代價：每一對位置都要算分數（N² 對），還要算投影，存整張權重表也要記憶體；位置資訊也得另外設計。

為什麼位置資訊要另外設計？卷積有局部位置先驗：結構上就假設鄰近的位置比較相關，每層只讀周圍的格子；這是寫進結構的假設，不是從資料學來的。這一層 attention 本身則不看位置。用本例試試：把左下 `[1,1]` 和右下 `[0,0]` 互換，左上的權重只是跟著換位置，變成 [0.3349,0.1651,0.1651,0.3349]，輸出仍是 [0.6698,0.5]。[1,1] 不管放在緊鄰的左下，還是對角的右下，左上都從它讀 0.3349，分不出遠近。token 若帶有前面卷積留下的位置線索，這一層才間接有位置資訊。

官方 YOLOv12 用位置卷積補上這一點：作者程式的 `pe` 對 V 做逐 channel 卷積（每個 channel 各用自己的一個小濾鏡），再加回 attention 輸出。它另外還有多 head、區域化（只讓同一區域內的位置互相讀取，下一節的主題）等結構，所以不能用這個單位矩陣初值的小例子，概括整個網路的行為。

常見錯誤：

- **漏掉 K 的轉置**：本例 Q、K 都是 `[1,4,2]`，`q @ k` 是 [4,2]@[4,2]，中間的維度對不上（2 對 4），PyTorch 直接報錯。
- **把 channel 當 token**：在本頁的排法（位置在前、channel 在後）下，例如寫成 `q.transpose(-2, -1) @ k`，會算出 [2,4]@[4,2]，得到 2×2 的 channel 對 channel 表。shape 合法、不報錯，但意義錯了；要的是位置對位置的 4×4 表。YOLOv12 作者程式在不用 FlashAttention 的分支裡，先把 q 轉成 channel 在前、位置在後，在那裡這樣寫才對，所以先看清楚軸的排法。
- **softmax 軸錯**：沿 query 軸做，變成每一欄加起來是 1，每一列加起來不一定是 1。
- **用 argmax 取代加權和**：argmax 只挑分數最大的那一個來源，失去「同時從好幾個位置混合讀取」；而且挑選這一步沒有梯度，傳不回 Q、K。
- **把 attention 權重當成因果重要性**：左上從左下讀 0.3349，只表示這一層、這一次讀了這個比例，不代表左下對最後預測的貢獻是 33%。輸出還受 V 的大小和後面每一層影響。

## 自主練習與答案

**練習 1：右下換成 [2,0]。**把第四個 token（右下）從 `[0,0]` 改成 `[2,0]`，投影仍是單位矩陣。第一個位置（左上）的權重和輸出會變成多少？

1. 先手算：第一個 query [1,0] 和四個 key 的內積、除以 √2 後的四個分數、四個分子（exp）、共同分母、四個權重，以及第一個位置的輸出。
2. 再執行程式，對照輸出裡以 `exercise` 開頭的兩行。

這題不用改程式：完整程式（Colab 裡那份）已經寫好這段練習，也寫著答案（`expected_row` 那行和下面斷言裡的數字）。手算完之前先別看那幾行，也別直接 Run All（全部執行），拿輸出代替自己的預測。

程式改的是 tokens 的副本 `exercise_tokens`：`exercise_tokens[0, 3]` 是第 0 張圖、索引 3（第 4 個）的 token，也就是右下。不直接改最上面的 `feature`，是因為前面的斷言核對的是原本的 tokens 和 [0.3349,0.1651,0.3349,0.1651] 那一列，改了就會失敗。這段練習也放在 `optimizer.step()` 之前：step 之後投影已經不是單位矩陣，答案會不同。

??? note "參考答案"

    第四個 key 變成 [2,0]。第一個 query [1,0] 和四個 key 的內積是 [1,0,1,2]，除以 √2 得 [0.7071,0,0.7071,1.4142]。

    四個分子（exp）是 [2.0281,1,2.0281,4.1133]，共同分母 2×2.0281+1+4.1133≈9.1695。第一列權重約 [0.2212,0.1091,0.2212,0.4486]，對應程式印出的 `exercise fourth-token [2,0], first weight row`。

    用四位小數的權重手算，輸出＝0.2212×[1,0]+0.1091×[0,1]+0.2212×[1,1]+0.4486×[2,0]＝[1.3396,0.3303]。程式用的是沒有四捨五入的權重，得到 [1.3395,0.3302]，對應 `exercise first output`。差的 0.0001 只是權重四捨五入造成的。

    第四個位置的權重最大：[2,0] 和 [1,0] 方向相同、長度兩倍，內積 2 比跟自己的內積 1 還大（見上面 `similarity` 那段）。第四個 V 也是 [2,0]，又拿到最大的權重，所以第一 channel 從 0.6698 增加到 1.3395。只改了第四個 token，第一列的四個比例就全變了，這就是「讀多少由內容決定」。

    不能沿用舊權重 [0.3349,0.1651,0.3349,0.1651]、只把第四個 V 換成 [2,0]（那樣會算出 [1.0,0.5]）。第四個 token 同時也是第四個 key：它的分數從 0 變成 2/√2，分子從 1 變成約 4.1133，共同分母從 6.0562 變成約 9.1695，所以四個權重都要重算。

**練習 2：目標改用原 feature。**這題要改程式：在 Colab 裡改「本節可修改的完整實驗」下面那一格；本機則改 `lesson_cases/15-attention-bridge.py`，兩者是同一份程式。把 `target = feature * torch.tensor([1., .5]).view(1, 2, 1, 1)` 改成 `target = feature`，其他不動。先預測：程式會停在哪一條斷言？為什麼？原本的七行輸出，還會印出哪幾行？再執行核對。

??? note "參考答案"

    程式照常印出前六行（和原本相同），接著停在 `assert not torch.allclose(grad_q, grad_k)`，報 `AssertionError`，最後一行 `backward/step through Q,K,V verified` 不會印出。

    目標改用原 feature 後，輸入和目標都有 channel 對調的對稱，三塊投影又都從單位矩陣出發，所以 Q、K 兩塊收到的梯度相同（用 float32 計算，最多只差捨入誤差）。`torch.allclose` 判定兩者相等，加上 `not` 就不成立。前一條斷言照樣通過：三塊梯度都不全為 0，只是 Q、K 兩塊彼此相同。這就是目標要把 channel1 乘 0.5 的原因。
