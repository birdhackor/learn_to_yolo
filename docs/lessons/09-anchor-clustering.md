# 9.2 尺寸聚類：先驗由哪一份資料決定

[在 Colab 執行本節](https://colab.research.google.com/github/birdhackor/learn_to_yolo/blob/lessons-v0.6.1/notebooks/09-anchor-clustering.ipynb){ .md-button }

上一節讓紅框相對於固定 anchor 學尺寸修正。若手填的兩種尺寸剛好符合資料，修正量就小；若資料主要是小方形和寬矩形，兩個 16×16 起點就沒有把這個差別提供給模型。現在仍保留每格兩槽、同一套中心解碼，只改這兩個尺寸由哪裡來。

材料是六個**訓練框**的寬高（pixel）：`[8,8]、[9,8]、[8,9]、[32,16]、[30,16]、[32,18]`。前三筆像小方形，後三筆像寬矩形。我們要用兩個代表寬高概括它們，讓每筆至少能找到一個相近的起點。這叫**聚類（clustering，分羣）**：把接近的資料放一羣，再找每羣的代表值；本頁的代表值就是 anchor。

兩個都填 16×16 是刻意選的弱基線：有兩槽，尺寸上卻只提供一種形狀。它與上一節的 16×16＋8×8 不同，後面也會把上一節設定算進來。

## IoU 在這裡比較什麼

先決定「接近」要量什麼。anchor 的工作是提供寬高起點，不提供圖片上的位置；因此輸入 `sizes [N,2]` 只收模型前處理後的寬、高，N=6，單位 pixel。沿用上一節的 [尺寸 IoU](09-anchors.md)，把比較的兩框中心對齊：

\[
I=\min(w_1,w_2)\min(h_1,h_2),\qquad
\mathrm{IoU}=\frac{I}{w_1h_1+w_2h_2-I}.
\]

8×8 對 16×16 的 IoU 是 64/256=0.25；8×8 對 9×8 是 64/72≈0.888889。IoU 越大越像，所以距離用 **1−IoU**，兩例分別是 0.75 與 0.111111。

![中心對齊的交集，以及六個寬高的兩羣與代表尺寸移動](../assets/diagrams/09-anchor-clustering.svg)

① 看黃色交集，寬和高各取較小者；②～④ 的橫、縱軸則是寬、高，圖上的一點代表一個尺寸，不是物件在圖片裡的位置。紫箭頭是代表尺寸從初始值移到羣平均。

為什麼不用平面上的普通歐氏距離？8×8 到 9×8 是 1，80×80 到 90×80 是 10；相同的相對形狀差，大框誤差卻大十倍。IoU 在兩框寬高都乘 10 時不變，因為交集、聯集同乘 100，兩例的距離都約 0.111。這讓聚類較直接回應我們的需要：大小不同的框，都用相對尺寸是否貼合來挑起點，而非讓大框的 pixel 誤差主導總和。

[YOLO9000](https://arxiv.org/abs/1612.08242) 的 dimension clusters（尺寸聚類）也是用這個距離找 anchor。本例只用六個人工寬高，不重現 VOC／COCO 資料、論文 k=5 或論文結果。

## 手做一次聚類

用 **k-means** 的反覆歸羣、更新結構，k 是羣數。要得到兩個 anchor，本例 k=2；每個格都用這兩個尺寸，所以 k 也等於每格槽數 A。羣中心指寬高平面上的代表值，並非圖片上的框中心。

先放兩個代表尺寸。本例固定取第一、最後一筆 `[8,8]`、`[32,18]`，叫 anchor0、anchor1，讓重跑有相同答案。真實使用常需試不同初始值，不能把這一組當成普遍最佳起點。

每筆各算兩個 `1−IoU`，歸到較小者：

| 尺寸 | 到 anchor0 [8,8] | 到 anchor1 [32,18] |
| --- | --- | --- |
| 8×8 | 0 | 0.8889 |
| 9×8 | 0.1111 | 0.8750 |
| 8×9 | 0.1111 | 0.8750 |
| 32×16 | 0.8750 | 0.1111 |
| 30×16 | 0.8667 | 0.1667 |
| 32×18 | 0.8889 | 0 |

例如 30×16 對 32×18：交集 480、聯集 576，距離為 `1−480/576≈0.1667`。結果前三筆歸羣 0、後三筆歸羣 1，記為 `[0,0,0,1,1,1]`。

接著把每羣的寬、高分別平均。羣 0 得 `[25/3,25/3]=[8.3333,8.3333]`；羣 1 得 `[94/3,50/3]=[31.3333,16.6667]`。用這兩個新代表值再歸羣、再更新，本例第 2 輪就不再改變。程式最多做 10 輪，空羣則保留原代表值：沒分到資料時，不從空集合算平均。

``` { .python data-excerpt="lesson_cases/09-anchor-clustering.py" }
def cluster(sizes, initial, steps=10):
    # sizes：[N,2] 的寬高，本例 N=6；initial：[2,2] 的初始 anchor
    anchors = initial.clone()
    for _ in range(steps):  # 最多 steps=10 輪
        # size_iou 回傳 [N,2]：第 i 列第 j 欄是第 i 個尺寸對第 j 個 anchor 的尺寸 IoU
        # argmin(1)：沿第 1 軸找最小值的位置，也就是每一列距離最小的是第幾欄＝群編號
        assignment = (1-size_iou(sizes,anchors)).argmin(1)  # 歸群結果，形狀 [N]
        updated = anchors.clone()  # 先複製舊值：空群（沒分到資料的群）就保留舊 anchor
        for k in range(len(anchors)):  # 這裡的 k 是群編號 0、1，不是群數
            selected = sizes[assignment==k]  # 用布林 mask 選出第 k 群的尺寸
            if len(selected):  # 這一群有分到資料才更新
                updated[k] = selected.mean(0)  # 沿第 0 軸（樣本）平均，得到 [平均寬,平均高]
        if torch.allclose(updated,anchors):  # 新舊 anchor 幾乎相同：不再變，停止
            return updated,assignment
        anchors = updated
    return anchors,assignment
```

`size_iou` 是上面的公式；`argmin(1)` 沿每列選最近的羣，`selected.mean(0)` 沿樣本軸分別算平均寬、平均高。`main()` 呼叫 `cluster(sizes,sizes[[0,-1]])`，把回傳的 `assignment` 叫 `groups`。

這裡的 cluster assignment 只記訓練前「尺寸歸哪羣」。聚類完成後，anchor 固定，再由上一節的訓練責任規則決定哪個槽學哪個 GT；羣 0、1 不是 positive／negative／ignore。

## 怎麼衡量 anchor 選得好

每筆框對兩個 anchor 算尺寸 IoU，取較大值，最後把六筆的最佳值平均，稱為**平均最佳尺寸 IoU**。程式的 `coverage` 也是這個量：0 到 1，越高表示這批框平均更貼近各自最像的起點。它不看位置、分數或偵測結果。

對兩個 16×16，六筆最佳值是 `0.25、0.28125、0.28125、0.5、0.5333、0.4444`，和約 2.2903，除以 6 約 0.3817。上一節的 16×16＋8×8 把前三筆改善成 `1、0.8889、0.8889`，後三筆不變，平均約 0.7093；小方形照顧到了，寬矩形仍只能配方形起點。

完整程式還沿用同一歸羣，將每羣寬、高各取中位數（排序後取中間值），得到 `[8,8]`、`[32,16]`。四組結果如下：

| anchor 來源 | anchor 寬高 | 評估材料 | 平均最佳尺寸 IoU |
| --- | --- | --- | --- |
| 弱基線 | [16,16]、[16,16] | 六個 train 框 | 0.3817 |
| 聚類＋平均 | [25/3,25/3]、[94/3,50/3] | 六個 train 框 | 0.9119 |
| 同一歸羣、逐維中位數 | [8,8]、[32,16] | 六個 train 框 | 0.9340 |
| 聚類＋平均 | [25/3,25/3]、[94/3,50/3] | 新來源 [4,40]、[40,4] | 0.1975 |

聚類的作用可接回上一節的修正量。以 16×16 為起點，32×16 要 `(ln2,0)`，8×8 要 `(−ln2,−ln2)`；換成本例平均 anchor，前者只需約 `(0.021,−0.041)`，後者約 `(−0.041,−0.041)`。六筆的 |tw|、|th| 最大約 0.077，弱基線則約 0.693。當 raw 從接近 0 開始，模型先有貼近常見尺寸的框，再學差異。

但中位數的 0.9340 高於平均的 0.9119，不能直接說中位數一定最好。標準 k-means 用平方歐氏距離時，平均是固定歸羣的最佳代表；**換成 1−IoU，平均更新只是容易手算的啟發式，不保證目標下降**，中位數也沒有一般最佳保證。

??? note "為什麼平均更新在這裡沒有保證"

    標準 k-means 用平方距離（兩點距離的平方）。這時羣中心取平均，正好讓羣內的平方和最小，理由如下。一個框到羣中心的平方距離，是寬相差的平方加上高相差的平方；羣中心的寬只出現在前一項、高只出現在後一項，所以寬和高可以分開求最小。以寬為例：設羣內 n 個框的寬是 \(x_1,\dots,x_n\)、羣中心的寬是 \(c\)，平方和展開成 \(\sum_i (x_i-c)^2=nc^2-2c\sum_i x_i+\sum_i x_i^2\)。這是 \(c\) 的二次函數，開口向上，頂點在 \(c=\frac{1}{n}\sum_i x_i\)，正好是這些寬的平均，所以平方和在這裡最小；高也一樣。

    因此，更新那一步（羣中心移到平均）不會讓總和變大；歸羣那一步讓每筆找最近的羣中心，也不會讓總和變大。所以標準 k-means 每輪的目標不增。

    換成 1−IoU 就沒有這個保證：取平均不一定讓固定歸羣內的距離總和最小，也不保證每輪目標下降。所以本例的平均更新只是容易手算的啟發式（heuristic：實用、通常有效，但不保證得到最佳解的做法）。逐維中位數也一樣，不能宣稱是這個目標的一般最佳解；完整程式在檢查「中位數較高」的斷言旁也註明，這只對這組資料成立，不是一般定理。

    ??? note "本例的數字與一個反例"

        歸羣固定為前三個一羣、後三個一羣時，把六個框到自己羣中心的 1−IoU 加起來：

        - 用平均 [25/3,25/3]、[94/3,50/3]：約 0.529，也就是 6×(1−0.9119)。
        - 用逐維中位數 [8,8]、[32,16]：約 0.396，也就是 6×(1−0.9340)。

        本例每個框的最佳 anchor 剛好就是自己那羣的 anchor，所以總距離等於 6×(1−平均最佳尺寸 IoU)。

        平均更新甚至可能讓目標變大。看一個只有兩筆資料、只分一羣（k=1）的例子：資料 [1,10]、[10,1]，初始羣中心 [1,10]。[1,10] 和羣中心相同，距離 0；[10,1] 對 [1,10] 的交集是 1×1=1，聯集是 10+10−1=19。這時總距離是 0＋(1−1/19)≈0.9474。取平均更新成 [5.5,5.5] 後，[1,10] 對它的交集是 1×5.5=5.5，聯集是 10+30.25−5.5=34.75。[10,1] 只是寬高對調，對正方形的 [5.5,5.5] 結果相同。所以兩筆對新羣中心的 IoU 都是 5.5/34.75≈0.1583，總距離變成 2×(1−0.1583)≈1.6835，反而變大。

        這兩個例子只說明取平均沒有保證，不表示中位數比較好。

新來源兩個極細長框的最佳 IoU 約 0.170、0.225，平均僅 0.1975，顯示這組 anchor 反映的是六個 train 框的形狀。平均值也會掩蓋個別不合：實際使用可按類別分組檢查尺寸貼合，但 anchor 仍不綁類別，每槽依舊輸出全部 C 類分數。

## 先固定來源切分，才收集寬高

只用 **train** 選 anchor。若 validation／test 的標註也參與聚類，就已利用評估資料挑設定，後續評估失去獨立性。依第 8 章的 [來源切分](08-own-data.md)，先將同來源整批分到 train、validation 或 test，再按模型實際 resize／letterbox 轉框，最後只收 train 的寬高。

例如原圖 128×128 縮成 64×64，原框 32×16 變成 16×8；若仍拿原圖 pixel 聚類，尺寸起點大兩倍。xyxy 也不能直接聚類：`[0,0,16,16]` 與 `[40,40,56,56]` 都是 16×16，位置差不該影響尺寸歸羣。

執行 `PYTHONPATH=. python lesson_cases/09-anchor-clustering.py` 或頁首 Colab，核對 groups、兩個平均 anchor 與表內四個統計。斷言核對歸羣、代表值、聚類平均分高於弱基線、中位數在這組資料較高，以及框和 anchor 同乘 2 時尺寸 IoU 不變。這個程式沒有模型、backward 或 AP；正式採用需用新舊 anchor 各訓練，再在同一份 held-out 資料比較。

anchor 尺寸與數量還要隨設定保存。這裡 k 從 2 增為 3，候選從 `4×4×2=32` 變成 `4×4×3=48`，配對與後處理都增加。更多起點可能貼合更多形狀，卻不會補回小物件在粗特徵中失去的細節：8×8 物件就算尺寸 IoU=1，在 stride 16 特徵裡仍比一格小。下一頁因此轉向增加較細的預測位置。

自主練習（手算即可，不必改程式；先自己想，再展開答案）：

1. 中位數 anchor 在這六筆的平均最佳尺寸 IoU 較高（0.9340 對 0.9119）。這足以選它，或宣稱 AP 改善嗎？
2. 把整張圖等比放大成 128×128（物件在 pixel 上也變 2 倍），anchor 要怎麼改？如果不改，32×16 的物件會怎樣？

??? note "參考答案"

    **第 1 題**：都不足。0.9340 只表示這六個訓練框的形狀更像 anchor。要知道 AP 有沒有改善，得用兩組 anchor 各訓練一個模型，再在同一份固定、沒參與訓練的資料上評估並比較 AP；不能讓 train 的尺寸統計代替泛化。

    **第 2 題**：anchor 的寬高也一起乘 2，尺寸 IoU 就保持一致（物件和 anchor 的寬高同乘一個倍數，IoU 不變；完整程式最後一個斷言檢查的就是這件事）。若只放大影像、不改 anchor，尺寸回歸的起點就不同了：32×16 物件變成 64×32，對 [31.33,16.67] 的尺寸 IoU 從約 0.941 掉到 0.255，tw、th 從約 (0.021,−0.041) 變成 (0.714,0.652)。anchor 乘 2 成 [62.67,33.33] 後，又回到約 0.941 與 (0.021,−0.041)。
