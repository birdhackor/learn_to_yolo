# 第 11 節陌生讀者審閱

審閱範圍：只讀 `docs/lessons/11-iou-loss.md`、`lesson_cases/11-iou-loss.py`；正文未引用或嵌入圖。讀者假設為懂基本 PyTorch／CNN，但不熟悉大學數學。已執行 `PYTHONPATH=. .venv-model/bin/python lesson_cases/11-iou-loss.py`，全部 assertion 通過；初始 loss 為 `1 / 1.2 / 1.310345 / 1.310345`，DIoU 一步後中心為 `[38.751488, 20]`、loss 為 `1.294497`。

有 3 個值得修正的問題，前 2 個有可重現的數值依據。

## 1. 正文的 CIoU 片段在「完全相同的框」會算出 NaN

- 位置：`docs/lessons/11-iou-loss.md:28–29`；對照 `lesson_cases/11-iou-loss.py:19` 及正文 `:34、:40`。
- 問題：正文寫 `alpha = (v / (1-iou+v)).detach()`，卻又要求讀者驗證相同框時所有 loss 都是 0。相同框的 `iou=1、v=0`，這段直接產生 `0/0`；實測 `alpha` 和 `ciou_loss` 都是 `nan`。案例程式有 `.clamp(min=1e-6)`，因此案例通過不能證明正文片段安全。初學者照抄片段會遇到與課文答案相反的結果。
- 具體修法：把正文第 28 行改成 `alpha = (v / (1-iou+v).clamp(min=1e-6)).detach()`，與案例一致，並補一句「分母下限用來處理相同框時的 0/0」。保留相同框的練習與 assertion。

## 2. 「往左移 8 pixel 仍不碰」其實已經碰到邊界，容易破壞零梯度的理解

- 位置：`docs/lessons/11-iou-loss.md:40`，連同 `:11、:13`。
- 問題：原 P 是 `[32,12,48,28]`；往左移 8 後變成 `[24,12,40,28]`，左邊界正好等於 G 的右邊界 24。交集面積仍為 0，但已到正文第 13 行提到的分段邊界。實際以案例函式計算，這時 IoU loss 仍為 1，中心梯度卻是 `[0.03125,0]`；DIoU 梯度為 `[0.04625,0]`。因此它不能延續前面「尚未碰到、IoU 梯度為零」的直觀，`仍不碰` 的表述也不準確。
- 具體修法：把練習改成「往左移 4 pixel，兩框仍隔 4 pixel」。此時 P 為 `[28,12,44,28]`，中心距離 20，包圍框寬 36、高 16，IoU loss 仍為 1 且梯度仍為 0；DIoU 為 `1 + 400/(36²+16²) ≈ 1.257732`。若想保留移 8 的版本，應明說「兩框邊界剛接觸，面積仍未重疊」，並把它改成觀察 PyTorch 邊界梯度的另一題。

## 3. GIoU 如何提供方向沒有示範，圖與數值練習也未補上這個缺口

- 位置：`docs/lessons/11-iou-loss.md:11、:19–21、:34、:36`；`lesson_cases/11-iou-loss.py:39–48`。
- 問題：課文算出 GIoU 的初始值 1.2，就直接進入 DIoU 的移動方向；案例也只檢查 IoU 梯度並更新 DIoU。對數學不熟的讀者而言，「多一個包圍框項」還不足以說明為什麼 GIoU 在沒有交集時會把 P 往左拉。正文稱「GT 紅框」，但本檔沒有圖，讀者也無法用顏色辨認 G、P、C 及距離線。
- 具體修法：在第 19 行後增加一個仍無交集的小移動：P 左移 1 pixel，union 仍為 512，C 面積由 640 降到 624，`L_GIoU = 2−512/624 ≈ 1.179487`，因此往左使 loss 下降。案例對同一個初始中心額外列印或檢查 GIoU 梯度；實測其為 `[0.02,0]`，接著明說「SGD 減去正的 x 梯度，所以 x 變小」。配一張小圖標出 G、P、C、`xyxy=[左,上,右,下]`，用線標出兩中心距離 ρ 和 C 的對角長 c；指出 `ρ²/c²` 的分子分母都是 pixel²，所以比例沒有單位。這能把符號、幾何與程式更新接在一起。

其餘內容不需要刪除。MSE 的 pixel² 尺度不可直接與約 1 的比例 loss 比效果、學習率 100 只適用本例、正格 mask 與其他監督仍須保留、單框更新不能證明 AP 提升等限制都寫得合適。歷史段落有原論文連結，並明確把四個 loss 的示範與完整 YOLOv4/v5 訓練配置區分開，沒有需更正的重要歷史斷言。除上述正文片段與邊界練習外，所示初始數值、DIoU 更新方向及案例的相同框檢查都正確。
