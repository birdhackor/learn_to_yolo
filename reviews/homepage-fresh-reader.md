### F1：手機縮放後，主圖文字無法正常閱讀

**嚴重性：高。位置：`docs/assets/diagrams/object-journey.svg:1`、`:5`、`:13–40`；`docs/index.md:14`。**

圖是 960×440 的橫式配置，上排四張卡、下排三張卡。在實測的 360px 全寬呈現中，卡片內容與底部說明需要放大才能辨讀。原圖的 15px 小字縮成約 5.6px，17px 文字約 6.4px，19px 標題約 7.1px。這還沒有扣掉網站在手機上的左右留白。

第一輪感受是「能看出有幾個階段，但看不清楚每個階段在做什麼」。首頁又把中心與 grid 的說明放在圖下，讀者必須在很小的圖上尋找對應。

**建議：**首頁採直式、少量步驟的流程圖，保留每步一句話；把需要辨讀數字的詳細橫圖留給教材。若仍保留橫圖，提供明確的「開啟大圖」入口，但不能只靠放大解決首頁的基本閱讀。

### F2：訓練、推論與評估的入口和依賴沒有畫清楚

**嚴重性：高。位置：`docs/assets/diagrams/object-journey.svg:17–31`、`:32–40`。**

上排只有「原圖與標註 → target → 模型與 loss → 更新參數」。第一次看時，會以為 target 是模型的輸入；圖中沒有「圖片進模型」與「target 用來比較預測」兩條關係。

下排從「decode 與還原」開始，沒有交代需要先把新圖片送進訓練後的模型取得輸出。編號 ⑤ 接在「④ 更新參數」之後，也容易把 decode 看成每次參數更新後的下一個訓練步驟。

「推論時：不需要真值 target，也不計算 loss」這個大標題覆蓋整個下排，包括「⑦ 獨立評估」。但評估卡又寫「真值配對」，讓讀者不知道評估究竟需不需要真值。NMS 直接箭頭連到評估，也沒有明示評估是另取有標註的資料做品質檢查。

**建議：**用三句話和三段明確流程呈現：訓練以圖片產生預測，再與真值算 loss 更新參數；推論以新圖片取得預測框；評估在未參與訓練且有標註的圖片上，比對預測與真值。首頁可以省去 loss 內部細節，但應保留這三者的關係。

### F3：「上圖的紅框」與實際圖像不符

**嚴重性：中。位置：`docs/index.md:14–16`；`docs/assets/diagrams/object-journey.svg:2–3`、`:13–21`。**

首頁寫「上圖的紅框中心是 `(16,20)`」，SVG 標題也說「同一個紅框」。實際圖內沒有圖片、紅色矩形框、中心點或 4×4 格線；只有文字 `xyxy = [8,12,24,28]` 和動畫紅點。紅點的用途要讀到最下方才知道是閱讀提示。

第一輪真的先尋找紅框與中心，最後只能依文字在腦中重建。這削弱了「先追一個物件」這張圖的用途，也可能誤認動畫紅點是物件中心。

**建議：**畫出 64×64 畫布、紅框、中心點與 4×4 格，並明確標示列／欄及座標方向；若首頁改為純概念圖，就同步刪除「上圖的紅框中心」這類要求讀者在圖中定位的敘述。

### F4：target 的四個數字與輸出最後一軸，需要讀者猜欄位

**嚴重性：中。位置：`docs/assets/diagrams/object-journey.svg:16`、`:21`、`:26`；`docs/index.md:16`。**

原始框是 `[8,12,24,28]`，target 卻變成「框 `[0,.25,.25,.25]`」。首次閱讀無法知道它仍是不是 `xyxy`，也不清楚第一個 `0` 是座標、類別還是格子編號。若它的順序是格內 `tx,ty` 加全圖比例 `w,h`，數值可以成立，但這個順序與各自單位沒有標出。

「輸出 `[B,4,4,7]`」同樣沒有說 B 或 7 的意思。「框 + 有無物件 + 類別」只讓我知道可能有 4+1+類別數，但圖只介紹「類別 0：紅色矩形」，沒有說有兩種類別，因而無法核對最後一軸為何是 7。事後讀閱讀路線才找到 B 的解釋，首頁本身仍沒有 7 的解釋。

**建議：**首頁移除這兩個需要軸與編碼前提的數值，留到 target 與模型輸出教材；若保留，必須一起標出四個欄位、像素／格內比例／全圖比例的差別，以及 `7 = 4 個框值 + 1 個物件值 + 2 個類別值`。不要只加更多未解釋符號。

### F5：評估卡把 TP／FP／FN 到 AP50 的關係壓縮得過頭

**嚴重性：中。位置：`docs/assets/diagrams/object-journey.svg:40`。**

「新圖片 → 一次真值配對」中的「一次」不知道是配對只做一次，還是每個真值只允許一個預測配到。接著「TP / FP / FN → AP50」容易讓首次讀者以為把某次的三個計數代入，就能得到 AP50；圖沒有提到依信心排序與 precision／recall 的關係。

**建議：**首頁只寫「在有標註的新資料上，比較預測與真值，衡量偵測品質」。若一定要放 AP50，寫「與真值比對 → AP50」並把定義連到評估教材，避免用一個簡化箭頭暗示計算方式。

### F6：開場與模型介紹在提供用法之前引入太多術語

**嚴重性：中。位置：`docs/index.md:3`、`:12`；`docs/learning-path.md:3–7`。**

開場要求讀者先對 `target`、head、loss 與 NMS「迷路」有感；緊接著又列 grid、anchor、anchor-free、DFL、配對、attention、推論 head。對只會基本 PyTorch 的讀者，這些多半不是已知問題，而是一串還不知道用途的新名詞。

我可以從兩個按鈕知道要點第一節或閱讀路線，但首頁沒有直接給出「先分類，再定位，再偵測，再讀版本機制」的完整階段。這件事在閱讀路線 `:3–7` 才清楚：第 0–7 章先完成靜態管線，第 8 章接自己的圖片，再讀演化與選修。

**建議：**開場先描述可理解的任務變化，將技術名詞清單移到閱讀路線；首頁放一行階段順序。「每節 notebook 可單獨執行」旁補一句「理解概念仍建議依閱讀路線」，避免把不需執行上一節理解為不需先學上一節。
