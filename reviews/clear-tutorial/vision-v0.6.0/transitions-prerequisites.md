## 入口當時承諾了什麼

閱讀路線〈開始前需要會什麼〉的必要門檻是基本 Python（含 class）；PyTorch 與 NN／卷積概念是「有了比較輕鬆」。數學承諾高中函數、指數／對數、向量與矩陣乘法即可，導數與連鎖律由第 0 章說明。不能把大學數學或完整 YOLO 主線閱讀當成支線必備。

ViT／DINO 選讀入口說「先讀第 1、3 章與 15.1 attention，再從 21.1 開始」，不要求先讀完所有 YOLO 版本，數學從向量、shape 與實際數字說起。這輪指定只讀了第 3 章的 identity 節；**沒有**讀 projection 與 plain／residual 對照，不能自動認為那些內容已教會。後續若真的依賴第 3 章其他兩節，須補讀實際相關前文再判銜接。

入口把新支線概括為紅／藍矩形「切成 patch → 交換資訊 → CLS 分類」，然後沒有類別答案的影像特徵學習，最後接回單物件定位。DINO（2021）已在入口與 15.1 支線註解中明確與同名 DETR 偵測器區分。第 21、22 章不需 assignment／AP；23.2 另外需要 4.1 框與定位、6.2 IoU。後兩份目前未讀，不能假裝知道其實際例子、座標或 IoU 評分口徑。

預設 CPU、固定 seed 合成資料，不下載權重；官方預訓練為另選操作。入口已限制分數只支持紅／藍矩形受控任務，並說隨機與自監督特徵在簡單分類都得到 64／64，不能據此判自監督較好。後續要核對這個 64 的資料組別、分母與凍結／訓練範圍。

## 從第 1 章實際學到的內容

材料是完整 8 張 32×32 黑底訓練圖，矩形固定 12×12，只改顏色與位置；紅＝類別 0、藍＝類別 1，圖號與類別答案是不同編號。圖 1／4 與 3／6 的位置相同、顏色不同，因此只靠位置無法全答對。這是小示範，沒有真實圖片能力測試。

RGB 是 channel 疊層，數值 0～1。NCHW＝圖片、channel、高、寬，batch 的 B 與 N 同義。輸入 `[8,3,32,32]`；分類輸出 `[8,2]` 是紅／藍兩個 logits，以 argmax 取類別。交叉熵直接接 logits，softmax／負對數公式放於選讀區且實際已讀。

卷積是局部乘權重、累加、加 bias，同一套權重在不同位置共用；每個輸出 channel 對應一個 filter。第一層 27 個權重加 1 bias、4 個濾鏡，112 參數。feature channel 不再固定代表 RGB。block、backbone、分類 head 在使用前有定義。ReLU 截斷負值；pooling 縮高寬；深層感受野擴大，但不是每個像素影響同樣強。

GAP 把各 channel 所有位置平均，因此平均這一步失去位置排列；分類只回答顏色可以這樣做，定位就要保留空間。兩個 block 後 `[8,8,8,8]`，GAP／flatten 成 `[8,8]`，線性 head 輸出 `[8,2]`。模型 1158 參數，每圖 479248 MAC，只算卷積／線性層，不能直接換秒數。

三步是 SGD 0.1、seed 7，確認梯度／權重更新但全部猜藍，沒有獨立測試。40 步是相同模型／圖／seed **重新初始化**，換 Adam 0.01；optimizer 與步數同時改，不能把差異只歸於步數。結果 8／8 是訓練圖正確率。表中第 1 點為尚未更新的 loss，第 40 點為第 40 次更新前的 loss；分類是全部 40 次更新後。0 loss 有 float32 捨入解釋，不能推出完美泛化。

行 145–150 表明確寫「第 40 次更新前」與「40 次更新後，這 8 張訓練圖的正確率」，不需由 JSON 猜量測時點。行 301 在查看 report.json 的地方解釋 JSON 是純文字欄位／值格式，用 `"seed": 7` 舉例，逐一對應 `initial_loss`、`last_pre_update_loss`、`train_accuracy`、`validation_accuracy=null`、`predicted_classes` 到正文的意義；未把讀者的 Python dict 背景當成他一定知道 JSON。這次只檢查說明是否在當地足夠，沒有開 JSON 或重跑訓練，因此沒有技術重驗數值的主張。

### 只用已讀內容作的小變化

若把兩個空間位置交換但送進 GAP 的數值集合不變，GAP 的每個 channel 平均不變；但不能據此聲稱整個 CNN 對任意圖像位置交換都不變，因為卷積本身先看局部鄰域。若要定位，應保存哪些特徵對應哪些位置，不只留平均向量。這個理由來自行 70–74。

## 從 3.1 實際學到的內容

residual 是 `y=x+F(x)`，主分支學修正，shortcut 原樣送 x 到加號。相加是同位置／同 channel 的逐值加法，不是 concat。shortcut 沒參數，但整個 block 有兩層卷積；shape 必須相同，broadcast 能讓錯誤靜默通過，不能把不報錯當設計正確。

本節主分支 Conv→ReLU→Conv，相加後無 ReLU、無 BatchNorm；與完整原版差異已先說。人工例是 1 channel、2×2、`[-2,-1,0,1]`，18 個卷積權重全零，所以 F(x)=0、y=x，包括負數。隨機更新例另建 4 channel、2 張 8×8，288 個參數；兩例在行 25 明確分開。

人工零分支的 `y.sum().backward()` 是測機制，沒有目標答案，也沒有 optimizer 更新；全零的兩層無法靠梯度下降開始學。另建隨機 block 才用 MSE 向全零目標更新兩步，其目的是確認末層收非零梯度與更新，並不驗分類／完整 ResNet 效果。

shortcut 在一維梯度中提供一個係數 1，但總梯度還有主分支，可能抵消。張量情形用 Jacobian 表每個輸入對各輸出的變化，不能把純量推導當完整圖；人工零分支關掉其他路，搭配 y.sum()，才看到 x.grad 全 1。相加後加 ReLU 會截斷負值，不能再說整個 block 對任意 x 恆等。

### 兩層不加 bias：在第一次需要它時是否清楚

行 13（第一個 F(x)=0 具體例子之前）已寫「**本節兩層卷積都不加 bias（偏置）。第一部分手動把主分支的權重全部設成 0，讓主分支輸出全為 0**」。第 1 章行 40 已教「加 bias」且行 191 寫參數公式的 +1 意義。因此讀到 3.1 行 25 的「18 個權重全設成 0」時，我可以只憑目前已讀內容知道不另有 bias 留下常數，兩次零卷積／ReLU 給零，這不是等到程式碼才補前提。

行 71再次說 `bias=False` 要去掉公式 +1，1 channel 時兩層 `2×1×1×9=18`、4 channel 時 `2×4×4×9=288`。18 與 288 不是換材料未說，也不應誤把第 1 章線性 head 的 18 參數當同一組。**這個前提與數量的局部銜接清楚**；沒有據此判整個第三輪通過。

### 只用已讀內容作的小變化

若零分支後加入 ReLU，輸出 `[0,0,0,1]`；對 y.sum() 而言，負值處梯度不再是 1，PyTorch 在 0 折點取 0。若兩條路由 `[2,4,8,8]` 與 `[2,4,4,4]` 相加，不能 broadcast；若主分支變為 `[1,1,1,1]`，卻可能 broadcast 且零值掩蓋錯誤。理由由行 49 與練習說明提供，不借未讀 projection 章。

## 從 15.1 實際學到的內容

這節材料不是第 1 章 RGB 原圖，而是一張**人工 2×2 特徵圖**、2 個 channel、shape `[1,2,2,2]`。channel0／1 兩張表和四個 token 內容均直接給出。按 row-major 左上、右上、左下、右下，把每位置的 channel 向量排成 token `[1,4,2]`：`[1,0]`、`[0,1]`、`[1,1]`、`[0,0]`。

flatten 只併位置軸，transpose 交換位置／channel；不能只用 reshape 假裝重排軸，否則 shape 合法但內容錯。輸出還原為圖也須同樣順序。

Q 是接收位置拿來查詢的向量、K 是來源拿來比對的向量、V 是真正讀走的內容。Q／K／V 是三份可學的線性轉換，投影不等於正射影。這個例子由三塊 2×2 單位矩陣初始，Q=K=V 才恰等於 token；訓練後通常分別改變。

query-key 內積除以 √d，再對來源軸 softmax；行是接收位置，列是來源位置，每行和為 1。d 是每個 Q／K 向量的特徵數，這裡 2，不是 token 數 4。第一行 `[0.3349,0.1651,0.3349,0.1651]` 加權 V 得 `[0.6698,0.5]`。attention 權重每次由輸入計算，不是 optimizer 更新的模型參數；`qkv.weight` 才是參數。attention 權重不能當最終預測的因果貢獻百分比。

單個 attention head 是一套 Q／K／V 與一張 N×N 權重表，和分類／偵測 head 不同。多 head 尚未實際教到如何切維度，這輪不能假裝從一句概括已學會程式與維度對應。

full attention 一層讀全部位置，但成本按 N² 配對成長。8×8→16×16 是 N 由 64→256、表由 4096→65536（16 倍），不是邊長平方只 4 倍。FlashAttention 不存整表但仍計算全部配對。內容本身沒有距離資訊，互換左下／右下只把讀取比例的列一起交換，左上結果不變；位置需要另外編碼或從前面的卷積帶來線索。

這個實驗再把 channel1 縮為 0.5 當人工重建目標，用 MSE、SGD 0.1 更新 QKV 一次。不是分類或偵測訓練、不證明泛化。broadcast 方向、梯度塊拆分、非零、兩兩不同、更新前後權重變化皆解釋在正文。`reconstruction loss` 是更新前算的 MSE，不能與第 1 章交叉熵或新分類正確率混為一項。

### 只用已讀內容作的小變化（讀者實際作答）

把右下從 `[0,0]` 改成 `[2,0]`，不能只改 V 沿用舊 weights，因為同一 token 也產生新的 K。第一 query 的四個內積變 `[1,0,1,2]`；新 softmax 的共同分母改變，四個比例都變。若只交換兩個來源 token 的排列，QK 的相應列與 V 的相應行同換，未帶位置編碼的左上加權和不變。這是理解輸入內容與順序區別，非重複輸出截圖。
