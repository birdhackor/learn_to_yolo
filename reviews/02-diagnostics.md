# 第 02 課陌生讀者審查

審查範圍僅為 `docs/lessons/02-diagnostics.md`、`lesson_cases/02-diagnostics.py`。本頁沒有引用圖片；未讀其他教材或大綱，未修改教材。讀者假設：有基本 Python／PyTorch 經驗，學過神經網路，但不熟悉本專案。

## 需要修改

1. **自主練習會讓原驗證集直接進入訓練集。** 教材第 57 行要求把 b 反轉的例子加入訓練，又維持原 held-out 資料。原始碼第 11、32–34 行顯示：原訓練只有兩種不同的點，各重複四次；反轉 b 後的兩種點恰好就是整個 validation 集。操作後它已不是「未參與訓練」的 held-out 集。建議改成：「這個介入實驗可以沿用原反轉資料比較預測，但加入訓練後，不能再把它當作 held-out 泛化證據。」若練習也要評估泛化，另產生未加入訓練的點，說明它們保持何種標籤規則與分布。不能只保留目前「評估應維持原 held-out」的答案。

2. **`body.grad` 無法照抄成有效檢查。** 教材第 57 行寫「若 body.grad 為 None」，原始碼第 16 行輸出也使用 `body.grad` 簡稱；但 `body` 是 `nn.Linear` 模組，它沒有 `.grad` 屬性。實際檢查是原始碼第 15、21 行的 `body.weight.grad`，教材第 26 行也已正確寫出。建議第 57 行與輸出訊息统一寫 `body.weight.grad`，或明說「檢查 body 內某個參數的 `.grad`」。否則新讀者直接輸入 `body.grad` 會得到 AttributeError。

3. **首次出現的術語還欠幾個短定義。** 教材第 9–12 行是整課操作索引，宜在這裡就補足：
   - 第 9 行：「標籤（label）：每筆資料的正確類別 ID」；同時限定 long／0、1 的契約適用於本課的兩輸出 `CrossEntropyLoss` 類別 ID 目標。現在的「兩類標籤應是 long」容易被理解為所有二元分類 loss 的普遍規則。
   - 第 10 行：「logits 是模型輸出的原始類別分數，尚未轉成機率」。第 34 行說 cross entropy 接 logits，但尚未解釋它是什麼。
   - 第 11 行：「overfit 小資料：刻意讓模型充分擬合／記住這幾筆訓練資料，以檢查訓練管線」。目前只要求 loss 能降低，讀者不容易判斷只小降一點是否算通過；可直接連到本例的訓練準確率 1.00。
   - 第 12 行：「`eval()` 切換為評估模式；`no_grad()` 暫停記錄自動微分的運算，評估時不用建立反傳路徑」。兩者目前並列而未說明作用不同。另加「validation 是用於監測／選設定的驗證集，test 是最後保留的測試集」，讓第 38 行的 validation 與第 12 行的 test 有明確角色。

   `detach()` 在第 26 行已短定義，足以理解；autograd 一詞沒有出現，沒有「首現未定義」問題。不過在第 26 行加一句「PyTorch 的 autograd 會記錄運算關係，據此反向計算梯度」，能把斷圖、backward、`.grad` 串起來。

4. **第一個案例的「loss 下降」不是程式實際呈現的結果。** 教材第 16 行標題宣稱「loss 下降，前半模型卻沒有學」，但原始碼第 12–16 行只在斷圖狀態做一次 backward，沒有 step，也沒有比較或輸出 loss。第 26 行的「甚至可能下降」作為原理解釋正確。建議標題改為「loss 可能下降，前半模型卻沒有梯度」，或在程式另實際呈現 head 更新後的 loss 變化。若維持目前短案例，改標題即可。

5. **「8 筆資料／20 步」可以更容易對照到輸出。** 教材第 5、45 行與程式數值相符，但原始碼第 32–34 行是兩種點重複四次，並非八個不同例子。建議第 45 行補「每類同一個點重複四次，共八筆、只有兩種不同輸入」。原始碼第 39、51–52 行使用從 0 開始的 step，最後 `step=19` 才是第 20 次更新；可在教材補一句，避免读者误以为少跑一步。

## 已核對且沒有問題

- 四個檢查點順序合理：先資料契約，再梯度與參數更新，再小資料擬合，最後評估未参与更新的資料。第 18–28 行搭配原始碼第 9–24 行，能實際找到並修掉 detach 造成的斷圖。
- shape、類別 ID、SGD learning rate 0.2、零權重初始化、20 次更新及「更新後才記錄 train／validation loss」都與原始碼一致。
- 已執行 `PYTHONPATH=. .venv-model/bin/python lesson_cases/02-diagnostics.py`，正常結束。輸出為 `step=0: 0.5945 / 0.7937`、`step=9: 0.2244 / 1.5204`、`step=19: 0.1236 / 2.0153`（train／validation loss），最終準確率為 `1.00 / 0.00`。教材第 47 行所述數值正確。
- 教材第 5、47 行與原始碼第 59 行均清楚標明人工診斷／分布變化，沒有把這組差異冒充真實影像模型的性能證據。
- 沒有需要刪除的離題或奇怪內容。主要應修正的是練習的 held-out 名稱與直接操作的細節；Colab 佔位未列入問題。
