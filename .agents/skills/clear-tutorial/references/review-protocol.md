# 依閱讀順序審閱教材

## 為什麼需要這個方法

熟悉技術的審查者可以讀完整節後重建作者意圖，卻仍漏掉初學者在中途需要的說明。程式能執行、術語有定義及圖檔存在，也不足以證明第一次閱讀順暢。

本方法把「第一次讀到這裡的理解」保存下來，再開放後續內容。不能用後文改寫先前記錄，也不以專家摘要取代讀者的理解過程。

## 審閱前準備

1. 指定讀者背景與工作範圍，遵循 [SKILL.md](../SKILL.md) 與已公布閱讀路線。未另指定時只假定基本 Python（含 class）與閱讀路線列出的高中數學；PyTorch、NN／CNN 經驗是較有幫助，不能當成入門節省略教學的理由。記錄各階段實際已讀的前文與已教概念，不假設 detector 術語或專案內部設計。
2. 凍結待審版本，保存來源路徑、內容指紋及正文／選讀／必要前文的分界。將正文按有意義的閱讀單位拆開：開場與第一個例子、答案規則、方法、程式與結果、解釋與練習。圖與它必需的圖說一起提供，不為湊長度拆開一句話；多個必要新概念同處一段時，分別安排焦點，不以整體流程的一組答案涵蓋全部。
3. 協調者保留全文和概念安排；第一次閱讀的審查者每次只收到目前正文單位和已讀的必要前文，不提前附選讀圖或解釋以補洞。不要提供作者的學習目標摘要、概念清單、答案、先前通過記錄、技術審查結論或未來段落。閱讀包不透露「這是補齊版」「這裡故意留了缺漏」等預期結果；若有多個材料版本，隱去版本提示。
4. 使用獨立 subagent 時，避免繼承作者對話，優先從無作者歷史的上下文開始。提供當前閱讀包，要求本輪不搜尋後文、程式實作或外部解釋。共同檔案系統不構成技術隔離，報告不得宣稱審查者無法存取全文；若提前看過全文，記為非盲讀，另找未讀過者檢查。
5. 依序閱讀者應能取得自己實際學過的前文，不能把「聽過」或前文提過名稱當成機制已教。前文選讀不列為所有順序讀者的已知；若某路線明訂為必要，記錄該路線與實際閱讀。跳讀者另開一輪，用教材提供的導覽；不可要求每一節假設零背景，也不可替順序讀者捏造已學過但前文沒教的知識。
6. 在每個必要新概念首次用於解釋機制、推理、使用規則或實作的閱讀單位，以及小節末，安排下述四題檢查。首次使用分概念回答，小節末檢查整體關係；可共用引證，但不能略過個別理解。若只審局部段落，明列實際提供的前文與限制；沒有首次使用處的紀錄，就不宣稱已驗證介紹時序。
7. 協調者建立或核對概念安排，列出必要概念、第一次使用處、依賴的已教概念、解釋處和學習結果。按任務與機制辨認，包含操作背後未命名的核心方法；不要只清點本文名詞。清單不先交首次閱讀者，正文首讀完成後才查覆蓋。

## 第一輪：分段揭露，當場記錄

協調者逐段提供閱讀包。審查者在取得下一段前保存以下內容，用讀者自己的話回答，未知的地方就寫「目前不知道」：

- 我目前理解正在做什麼，以及為什麼要做。
- 此刻已出現的輸入、答案、編號、圖中元素與箭頭，各代表什麼。
- 下一個動作預期改變什麼；我從哪一句或哪個圖中知道。
- 哪個位置需要猜測、回讀或借助課外知識；引用當時的原文。
- 我需要看見但尚未看見的素材、對應或圖解。
- 我理解這次做法的理由與相關概念的差別，還是只能照指示操作；原文在哪裡提供了理由。
- 資料、任務、模型、表示、維度或 loss 改變時，為什麼換、與前例哪些關係相同；簡化例子怎麼連回一般方法。

閱讀程式前，另確認讀者已知道它要實現的任務，以及這段是手工示範、計算梯度、更新參數或評測。程式後再確認輸出代表什麼、能支持什麼結論；不要只要求說出 tensor 的形狀。

不要求讀者在教學之前已懂新概念。作者先提問、下一段立即解答，可以是合理安排；若正文已拿未交代的編號或機制進行推理，才構成需要修正的斷點。後文解釋之後，追加「在何處才釐清」，保留原先的疑惑記錄。

### 先驗證正文，再補讀選讀

先不開選讀、附錄與外部解釋，沿正文完成當場判斷。只有標為必要且實際已讀的前文可作先備依據，不能用前文選讀替所有順序讀者補知識。保留原頁中的選讀標記與連結資訊；連結存在不等於解釋已讀，也不把頁尾圖提早移進閱讀包。必要圖在主文缺席時應記錄，不由協調者悄悄補上。

先完成本輪範圍的整段正文路線（含後續待審章節）並保存判斷，才補讀選讀，另記新增的理解、解決了哪個早期問題，以及那項內容是否應放回首次需要的位置。選讀補足不能消除正文原有缺口。若圖或公式雖難，但承載基本概念，仍依用途判斷是否屬正文；完整推導、進階變體與重做細節可保留選讀，不一律搬回主文。若同一讀者已補讀選讀才繼續後續正文，記錄這個先備差異，不聲稱後續為純正文首讀；含選讀路線的證據分開保存。

### 主要新概念的四題檢查

在上述兩個時點，各用讀者自己的話回答四題：

1. 這次檢查的新概念或方法（小節末則為整體方法）是什麼？它扮演什麼角色，與前文有什麼關係？
2. 為什麼要在這裡教它？它回應什麼問題，或增加什麼理解與能力？
3. 它如何使用？需要什麼、得到什麼，以及得到的結果如何供後續使用？
4. 例子、圖表或推導說明了什麼？它們支持哪些理解或結論，哪些還不能推出？

四題檢查當次必要概念或整個方法。先說清楚自己回答的對象；子步驟只作補充，不能把「這一步改哪個數字」當成「這個方法為什麼要學」。同一段首次使用多個必要概念，要分別留下理解與缺口，再於小節末連成整體；例如 CNN 流程的答案不能代替 ReLU、pooling、感受野或交叉熵的介紹。上位類別已定義，不等於新的命名方法已介紹；方法未被命名也可能是必要漏項。

重要新概念或命名方法首次進入正文教學時，核對完整名稱（若為縮寫）、中文意義、當下所需含義、整體角色與學習理由。完整名稱不能代替概念解釋；導覽定位不能自動代替正文教學。承認導覽與前文已提供的背景，已教過的前置不用每頁重講，但不能靠未讀後文或課外知識補足目前介紹。

每題的每個核心主張，都要引用當下已讀原文或指出圖中具體依據，不能只在整段答案後附一段概括引文。按以下狀態標記：

- **正文明說：**當前正文直接支持這個主張。
- **導覽／前文已教：**引用實際已讀的位置；不把導覽簡介寫成正文已完整解釋。
- **由已讀內容推得：**列出支持推論的句子與推論關係；合理推得仍不等於作者明寫。
- **目前不知道：**指出尚缺哪個主張；沒有來源就不借常識作答。

在同一檢查時點，為每個首次進入正文教學的重要命名方法填一份**方法介紹原句對照**。這是四題答案的證據整理，不新增問題；不用對每個熟悉名詞建立清單。寫明方法名稱，分別核對方法本身、上位類別及子步驟，避免用後兩者代替方法總覽。

```text
方法名稱／閱讀單位／當時已讀範圍：
方法身分與整體角色：原句與位置／來源狀態／當下判定與理由／問題編號（若有）
方法目的：原句與位置／來源狀態／當下判定與理由／問題編號（若有）
本節步驟與方法的關係：原句與位置／來源狀態／當下判定與理由／問題編號（若有）
```

來源狀態沿用上述四種；當下判定用「已足夠／需補說明／合理待教」。可引用四題已有的逐項證據編號，不必重複抄寫原句；三項的來源狀態與判定仍分開記錄。沒有原句支持就記缺項，不把自己整理出的流暢答案寫成作者原句。相鄰幾句可共同明說一件事，不強求固定句型；引用上位類別或局部操作時，要檢查原文是否真的交代了它與該方法的關係。前文確實完整教過的方法可引用，導覽的簡短定位則按實際內容記錄。

填完立即核對 issues：若需拼接導覽、上位類別與局部機制，才能知道方法身分、目的或當前步驟用途，將尚缺的連結與實際負擔列為概念介紹／教學時序問題，至少記增加理解負擔。即使能合理推得、能答對四題，也不能只留下 inferred／unknown 而省略這項問題。保留來源已教部分，不誇稱整個方法完全未教；正常依已教知識推導不算缺漏。合理待教須說明當下尚不需要哪個細節，不能把內部機制的延後套到基本方法介紹。

整體答案應連成「是什麼 → 回應的問題 → 得到什麼與用途」，讓只懂前文的人也能理解。不要用術語列表、tensor shape 或正確復述某個操作取代整體介紹。

這四題適用於概念、架構、演算法、推導、評估與訓練，依內容決定需要的材料與結果。涉及訓練才分開訓練材料、訓練後成果及使用時的輸入輸出；一般概念不強求 optimizer、模型產物、梯度或訓練數據。沒有比較主張，不要求證明優於其他方法；機制探索本身可有明確學習目的。沒有圖或小算例時依實際文字、推導回答，未看的圖標為未驗證。

開場提問後立即解釋，不算缺漏。到必要概念已被用來解釋機制、推理、使用規則或實作時，若名稱含義、整體角色或學習理由仍缺必要介紹，必須將缺項具體列入問題，不能保留未知卻判整體通過。尚未展開、也未要求拿來推理的細節可記為待教，不自動報缺；說明為什麼目前不需要它。

「不用操作」不構成基本介紹可延後的理由。若已用某概念解釋使用規則、錯誤或結果，當下就需要其基本作用。例如要求「不要先做 softmax」時，應已交代 softmax 在分數與機率之間做什麼；不必當場教完整微分公式。只由上下文猜出用途或能避免錯誤，不足以判基本介紹完整。

問題要附當場原文、已知部分、仍需猜的部分及實際影響。後文解釋只能追加後來澄清的位置，不能將首次使用時的未知或問題回寫成已知。讀完後復述正確，也不能消除已記錄的閱讀斷點。

後文補足方法總覽時，在原問題追加「後來已釐清」及位置，並保留首次使用時的介紹／時序負擔；不能只保留名稱 optional，讓先前的概念問題從最後報告消失。未來是否需要調整介紹位置，依首次讀者當時需要的內容決定。

每個檢查時點保存以下格式與上述方法原句對照；四題各一份答案，不增加核心題目：

```text
小節／閱讀單位／檢查時點：首次使用／小節末
當時已讀範圍：
閱讀路線：只讀正文／補讀選讀；本次可用的先備概念與位置：
題號／回答的主要概念或整個方法：
用自己的話回答：
核心主張逐項列出：主張／狀態／來源位置與引文／推論關係（若有）
目前不知道的部分，以及當下是否已需要它：
具體問題（沒有則記無；必要介紹的未知不能省略）：
後來何處釐清（後續追加，不改早期判斷）：
```

#### 第二題的理由完整性與限定句的用途

第二題檢查的是理由是否由已讀內容成立，不只檢查有沒有「為什麼」的句子。若方法用來突破能力限制，在原四題紀錄中分別保存以下主張的原句或圖中依據：原方法能做什麼、哪個具體情況暴露限制、新機制如何改變限制、對當前任務有什麼用途。只有「增加表達能力」「更複雜」「效果更好」或數學性質，尚未連到任務時，列需補說明；不由審閱者用課外知識補成完整理由。若引入是為了計算便利或統一表示，就核對該項需要，不要求虛構能力反例。

對用途不清或新增的限定／例外，保存它回應的當下疑問、避免的具體誤解、依賴的已教概念，以及本位置的用途。技術上成立但突然引入未教架構或其他旁支時，按影響列教學時序／閱讀負擔問題；修正主敘述或安排位置。解讀結果所需的限定保留，不一律移到選讀。這些是原四題與問題紀錄的判準，不新增每句都要填的表格。

正誤例與技術說法可成立但教學不足的區別，見 [SKILL.md 的方法理由與限定句示範](../SKILL.md#方法理由要連到具體問題)。首次閱讀包不附待審節對應的示範、作者判斷或預期答案；審閱者若已看過相同算例及答案，記錄這項提示限制，不宣稱未提示的首次理解。

**審閱不足示範。**「原文說 ReLU 能增加表達能力，也證明多層乘加能合併，所以第二題通過。」引文存在，但沒有證明原文已交代分類任務受什麼限制，以及非線性如何回應它；這個判定不足以通過。

**正確審閱示範。** 原文若只教層可合併，記「正文明說：多層乘加的組合性質；目前不知道：這如何限制本節分類，以及加入非線性如何改變。需補說明：任務限制與機制連結」。若正文也展示不可直線分隔的四點、ReLU 的新表示、可核對的分數與判定，才逐項引用這些位置支持理由。手選參數算例只支持表示能力，不當成訓練或泛化通過。

### 例子與完整復述

每個主要例子加入一個有意義的小變化，請讀者預測並說理由，保存題目、預測、理由、原文依據和暴露的缺口。測試要對準概念的因果關係或常見誤解，不能只換數字重套公式。例如按已教機制區分卷積跨位置共用與跨通道權重，或解釋更換類別編號為何不應改變分類問題；偵測可在已學格子分配後移動框中心，或在已學 anchor 解碼後只改 anchor 寬度並解釋幾何影響。

變化只使用當前已教的概念，不偷渡尚未教的變體，也不要求每節比較所有替代方法。不用原樣照抄輸出充當理解測試；有歧義時，不把答錯怪在讀者身上。若問題需要的理由未教，列為教材缺口；補教後答對只能作修後證據，不能算原文已通過。答案正確但理由需課外知識，也不能當成正文已教會。

若正文已教對角分類的資料、答案與分數門檻，可保持它們不變，問拿掉中間非線性、只增加乘加層是否能分開資料。保存讀者如何連起層可合併、直線邊界與這組資料的限制；只答「不能，因為沒有 ReLU」不足。尚未教的連結標成缺項，不能提前補答案。此例只供協調者安排測試，不在閱讀前交給首讀者。

讀完才做完整復述；復述正確不能消除已記錄的閱讀斷點。

### 概念覆蓋與遺漏核對

正文首讀完成後，協調者以概念安排核對每個必要概念的首次使用紀錄、先備依據和解釋位置，辨認未命名的核心方法及資料／模型／維度／loss 的轉換。例子能算對，不代表已定位梯度下降法；每個名詞有短句，也不代表 NN 到 CNN 的依賴已教。檢查全書入口及階段轉折是否已建立任務背景與學習動機。

漏掉的焦點應補查，報告註明由協調者或補充審查發現，不能算原讀者成功報出，也不能把已讀後文者的補查改稱首次盲讀。技術審閱可協助確認必要知識，但不能拿專家答案回寫首讀。

## 圖與頁面的必要檢查

即使本節沒有圖，也要明確回答：

1. 讀者是否必須自行想像圖片內容、空間位置、資料流或標籤對應才能理解？
2. 哪個具體問題需要素材或圖解回答？文字是否已經足以清楚說明？
3. 若已有圖，它是否真的回答這個問題，而非只是一張架構裝飾？

在有瀏覽器工具時，以實際呈現的頁面檢查桌面與手機，例如 1280×800 與 390×844；分段盲讀時不展示尚未解鎖的內容。沒有工具時記為未驗證，不能用建置成功代替視覺檢查。

確認素材看得見、必要字與線可讀、圖說對得上、箭頭能理解；桌面正文內的基本解說不能依賴點擊放大。動畫停止或停用時也應保留關鍵資訊。

在原頁面檢查第一次需要說明的位置與實際圖文位置，記錄折疊狀態、前後相鄰關係及為理解當下內容而發生的捲動／跳轉。感受野正文只叫讀者先記結論、基本示意卻在頁尾選讀，就是需要判斷的安排；圖存在且字清楚不足以通過。正常複習已教前文與補當下缺口分開記錄，再評估多個小斷點的累積負擔。分段提供圖時仍保留原位置資訊；未看實際頁面的閱讀路徑只標為文字來源檢查，不宣稱版面已驗證。

YOLO 圖要核對框、候選點、座標單位和正文數字，並檢查 Zensical 的數學排版與頁面切換；原始 SVG 正確不代表頁面呈現正確。

## 第二輪：技術與證據

第一次閱讀問題修正後，另由未參與撰寫的人檢查：

- 任務、輸入、答案與實驗設計是否一致；有沒有資料洩漏、顏色與形狀綁定等重要混淆因素。
- 程式究竟做了什麼；真正更新的是哪些參數，座標、張量、圖與正文是否一致。分清手算、直接更新 logits、完整小模型訓練與評測。
- 每個數字是否能回查到指定版本的證據，分母與判準是否清楚；選定模型和實際部署是否相同。
- 得分是否混用分類正確率、IoU、AP50 或 mAP50–95；真值配對、IoU 門檻、插值與類別平均是否交代。正常結束、訓練 loss 下降與泛化能力各需要不同證據。
- 因果結論是否有控制比較；資料足夠、參數不足或某技術更好，不能只靠印象下判斷。
- 淺白敘事是否建立新的誤解。依本次內容核對，例如 CNN 早於 2012 年、分類任務不等於圖片必須只有一個物件、標準卷積的通道權重與權重綁定設計不同、MSE 並非絕對不能分類；PyTorch cross_entropy 接 logits，內部採數值穩定的 log-softmax 等計算。不是每次審閱都要求查全部例子。

逐項核對首次閱讀問題的來源支持。原文已有部分說明時，保留它已教的部分，只指出仍缺的銜接；不要由名稱未展開推成角色、目的與成果全部未教。將名稱補充、介紹不足、時序負擔、技術錯誤及證據不足分開評估。

對不確定的知識查原論文或官方文件，記下支持的具體位置。需要執行的檢查應與疑點相稱；不要為一處文句修改重跑整套訓練。

版本比較還要區分論文主張、本專案的實測與機制推論，核對起點、改動、收益與代價。資料、模型或訓練設定不同的小示範，不構成公平的效果比較。

## 第三輪：前後銜接

技術修正後，由另一位讀者從前面相關小節讀到本節及下一節。依各階段的進入知識與學習結果，檢查新概念順序、未命名的核心方法、例子如何連回一般方法、資料／維度／loss 等轉換的理由，以及同一術語的意義是否改變。先走只讀正文的路線，確認前文真的提供必要背景，再檢查選讀分界與實際頁面的圖文位置。

如果新內容改變了教學目標或順序，回查受影響的前文與導覽。若只是文字局部修正，重查相關閱讀單位和過渡，不盲目重做全書或 GPU 實驗。

## 問題記錄與通過規則

每一個問題至少保存：

```text
code commit／來源與圖的內容指紋／小節／閱讀單位：
目前可見的原文與圖：
閱讀路線與來源種類：正文／必要前文／選讀；圖文原位置與折疊狀態：
當時讀者的理解：
卡住的位置及原因：
能否只憑已讀內容回答：是／否；依據：
原文已交代的部分與仍缺的主張：
缺少的說明或圖解：
後文是否釐清，以及何處才釐清：
建議修正：
問題類型：名稱補充／概念介紹／方法理由／限定句用途／先備依賴／轉換理由／教學時序／正文與選讀／圖解／閱讀路徑／技術／證據
嚴重程度：阻礙主要概念／增加理解負擔／選讀改善
分級理由：實際影響哪個理解、推理或操作
猜測、回讀或跳轉的原因；與其他斷點的累積影響：
修正後的實際複查：
```

依實際影響分級：必要背景不足，導致主要概念、學習目的或使用方式無法理解，屬阻礙主要概念；需要拼湊、猜測或回讀才能銜接，屬增加理解負擔；名稱補充或不影響當下主要理解的細節，屬選讀改善。重要縮寫未展開仍須記錄，但若角色與含義已清楚，不因名稱一項就升為主要概念阻礙。若完整名稱或其解釋承載必要含義，則依缺失的含義造成的影響判定。

存在阻礙主要概念的問題、必要說明／圖解缺漏，或正文仍需猜測、拼湊、回讀補足必要理解時，列為待修，不判該範圍首次閱讀通過；即使最後一類分級為增加理解負擔，也不能因操作尚能完成而放行。正常複習前文不自動算缺漏。不影響主線理解的名稱補充、選讀改善與其他可保留建議，逐項寫保留理由；多個斷點累積損害主線時，按整體影響處理，不能逐項降級後概括通過。

技術正確、能答四題、原句存在或程式能跑，均不能單獨代替閱讀理解證據。完成條件還包括概念覆蓋、只讀主文可成立、小變化的理解理由，以及受影響閱讀路徑的檢查。沒有做的視覺檢查、程式執行或獨立閱讀，標記為未驗證；不得補寫成已完成。作者不能只增加一則遙遠的註解便宣稱問題解決，要在讀者需要它的位置複查。

方法理由仍缺具體限制／需要、新機制與任務的必要連結時，不因寫有「增加能力」就通過。限定句若必須借助未教概念或猜測作者用意才能理解，也列待修；技術正確的問題不改標成技術錯誤。單純不影響主線的文字精簡建議可以附理由保留，依實際閱讀影響分級。

逐段原始紀錄存入 `reviews/clear-tutorial/`；保留原始卡點並追加修正後複查。既有完整頁面閱讀或技術審查不得在缺少逐段原始紀錄時改標為盲讀通過。

AI 審閱即使通過，也只是找問題的輔助。可能時請實際目標讀者說出卡住處，並用這些回饋調整後續審閱標準。
