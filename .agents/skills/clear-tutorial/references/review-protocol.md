# 依閱讀順序審閱教材

## 為什麼需要這個方法

熟悉技術的審查者可以讀完整節後重建作者意圖，卻仍漏掉初學者在中途需要的說明。程式能執行、術語有定義及圖檔存在，也不足以證明第一次閱讀順暢。

本方法把「第一次讀到這裡的理解」保存下來，再開放後續內容。不能用後文改寫先前記錄，也不以專家摘要取代讀者的理解過程。

## 審閱前準備

1. 指定讀者背景與工作範圍，遵循 [SKILL.md](../SKILL.md) 的約定：有基本 Python／PyTorch、NN／CNN 理解，大學數學學過但未必熟練；也照顧閱讀路線已承諾的較低門檻。不假設 detector 術語、專案內部設計或前文未教的知識。
2. 凍結待審版本，保存來源路徑與內容指紋。將正文按有意義的閱讀單位拆開：開場與第一個例子、答案規則、方法、程式與結果、解釋與練習。圖與它必需的圖說一起提供，不為湊長度拆開一句話。
3. 協調者保留全文；第一次閱讀的審查者每次只收到目前單位和已讀前文。不要提供作者的學習目標摘要、答案、先前通過記錄、技術審查結論或未來段落。
4. 使用獨立 subagent 時，避免繼承作者對話，優先從無作者歷史的上下文開始。提供當前閱讀包，要求本輪不搜尋後文、程式實作或外部解釋。共同檔案系統不構成技術隔離，報告不得宣稱審查者無法存取全文；若提前看過全文，記為非盲讀，另找未讀過者檢查。
5. 依序閱讀者應能取得自己實際學過的前文。跳讀者另開一輪，用教材提供的導覽；不可要求每一節假設零背景，也不可替順序讀者捏造已學過但前文沒教的知識。

## 第一輪：分段揭露，當場記錄

協調者逐段提供閱讀包。審查者在取得下一段前保存以下內容，用讀者自己的話回答，未知的地方就寫「目前不知道」：

- 我目前理解正在做什麼，以及為什麼要做。
- 此刻已出現的輸入、答案、編號、圖中元素與箭頭，各代表什麼。
- 下一個動作預期改變什麼；我從哪一句或哪個圖中知道。
- 哪個位置需要猜測、回讀或借助課外知識；引用當時的原文。
- 我需要看見但尚未看見的素材、對應或圖解。

閱讀程式前，另確認讀者已知道它要實現的任務，以及這段是手工示範、計算梯度、更新參數或評測。程式後再確認輸出代表什麼、能支持什麼結論；不要只要求說出 tensor 的形狀。

不要求讀者在教學之前已懂新概念。作者先提問、下一段立即解答，可以是合理安排；若正文已拿未交代的編號或機制進行推理，才構成需要修正的斷點。後文解釋之後，追加「在何處才釐清」，保留原先的疑惑記錄。

每個主要例子加入一個有意義的小變化，請讀者預測並說理由，例如在已學過格子分配後移動框中心，或在已學過 anchor 解碼後只改 anchor 寬度。變化只使用當前已教的概念，不用原樣照抄輸出充當理解測試；有歧義時，不把答錯怪在讀者身上。

讀完才做完整復述；復述正確不能消除已記錄的閱讀斷點。

## 圖與頁面的必要檢查

即使本節沒有圖，也要明確回答：

1. 讀者是否必須自行想像圖片內容、空間位置、資料流或標籤對應才能理解？
2. 哪個具體問題需要素材或圖解回答？文字是否已經足以清楚說明？
3. 若已有圖，它是否真的回答這個問題，而非只是一張架構裝飾？

在有瀏覽器工具時，以實際呈現的頁面檢查桌面與手機，例如 1280×800 與 390×844；分段盲讀時不展示尚未解鎖的內容。沒有工具時記為未驗證，不能用建置成功代替視覺檢查。

確認素材看得見、必要字與線可讀、圖說對得上、箭頭能理解；桌面正文內的基本解說不能依賴點擊放大。動畫停止或停用時也應保留關鍵資訊。

YOLO 圖要核對框、候選點、座標單位和正文數字，並檢查 Zensical 的數學排版與頁面切換；原始 SVG 正確不代表頁面呈現正確。

## 第二輪：技術與證據

第一次閱讀問題修正後，另由未參與撰寫的人檢查：

- 任務、輸入、答案與實驗設計是否一致；有沒有資料洩漏、顏色與形狀綁定等重要混淆因素。
- 程式究竟做了什麼；真正更新的是哪些參數，座標、張量、圖與正文是否一致。分清手算、直接更新 logits、完整小模型訓練與評測。
- 每個數字是否能回查到指定版本的證據，分母與判準是否清楚；選定模型和實際部署是否相同。
- 得分是否混用分類正確率、IoU、AP50 或 mAP50–95；真值配對、IoU 門檻、插值與類別平均是否交代。正常結束、訓練 loss 下降與泛化能力各需要不同證據。
- 因果結論是否有控制比較；資料足夠、參數不足或某技術更好，不能只靠印象下判斷。

對不確定的知識查原論文或官方文件，記下支持的具體位置。需要執行的檢查應與疑點相稱；不要為一處文句修改重跑整套訓練。

版本比較還要區分論文主張、本專案的實測與機制推論，核對起點、改動、收益與代價。資料、模型或訓練設定不同的小示範，不構成公平的效果比較。

## 第三輪：前後銜接

技術修正後，由另一位讀者從前面相關小節讀到本節及下一節。檢查新概念出現順序、例子轉換、前文是否真的提供必要背景，以及同一術語的意義是否改變。

如果新內容改變了教學目標或順序，回查受影響的前文與導覽。若只是文字局部修正，重查相關閱讀單位和過渡，不盲目重做全書或 GPU 實驗。

## 問題記錄與通過規則

每一個問題至少保存：

```text
code commit／來源與圖的內容指紋／小節／閱讀單位：
目前可見的原文與圖：
當時讀者的理解：
卡住的位置及原因：
能否只憑已讀內容回答：是／否；依據：
缺少的說明或圖解：
後文是否釐清，以及何處才釐清：
建議修正：
嚴重程度：阻礙主要概念／增加理解負擔／選讀改善
修正後的實際複查：
```

存在阻礙主要概念的問題，或必要圖解缺漏時，不能判通過。沒有做的視覺檢查、程式執行或獨立閱讀，標記為未驗證；不得補寫成已完成。作者不能只增加一則遙遠的註解便宣稱問題解決，要在讀者需要它的位置複查。

逐段原始紀錄存入 `reviews/clear-tutorial/`；保留原始卡點並追加修正後複查。既有完整頁面閱讀或技術審查不得在缺少逐段原始紀錄時改標為盲讀通過。

AI 審閱即使通過，也只是找問題的輔助。可能時請實際目標讀者說出卡住處，並用這些回饋調整後續審閱標準。
